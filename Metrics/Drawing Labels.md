# 図面ラベル（`Drawing Label2`） — 計測記録

結論は [Findings「Drawing Labels」](../Findings/Drawing%20Labels.md)。ここには実測の表・
読み出した式とレイアウトのダンプ・使ったコード・切り分けの経緯（#177 の読み違いと測り直し）を置く。

> ここには計測の手順と結果だけを置く。結論・解釈は Findings にある。

シートレイヤのビューポートに図面タイトル・縮尺・図番を出す PIO。**ラベルレイアウト**
（ラベルの絵の組み方）を SDK から per-instance で組むときの実測。

調査の発端は「軸組図（断面ビューポート）ごとに、その真下へ図面タイトルだけを出したい
（図番は出さない）」という要求（[issue #149](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/149)）。

## 測った環境

- VW 2026 / mac・日本語版。新規の空図面（#249 は既定のテンプレート `Default.sta` から開いた
  図面と `OpenDocumentPath(nullptr)` の空の図面も）。各節に使ったプローブと issue を書く。
  プローブ（`probes/runtime/…`）は役目を終えたので消してある。

## どのオブジェクトか

| | |
| --- | --- |
| universal 名 | `Drawing Label2` |
| 内部 ID / スタイルのサブタイプ | **642**（`kInternalID_DrawingLabel2`。[Parametric Objects](../Findings/Parametric%20Objects.md) / [Symbols](../Findings/Symbols.md)） |
| 旧版 | `kInternalID_DrawingLabel = 96`（`Drawing Label`。VW 2026 の既定は 2 のほう） |

`sdk-grep` で `DrawingLabel` を引いて当たったのは、上の 2 つの内部 ID 定数と
`kObjectStylesDrawingLabelFolder` だけだった。

## パラメータ（16 件）

新規に作った直後の実測（VW 2026 / mac・日本語版）。欄型は `EFieldStyle`
（`3`=実数 / `4`=文字 / `7`=座標 / `8`=ポップアップ / `1`=整数 / `2`=真偽 / `14`=レイアウト編集）。

| universal 名 | 欄型 | 作った直後の値 | 表示名 |
| --- | --- | --- | --- |
| `ScaleFactor` | 3 | `1` | 記号の倍率 |
| **`Title`** | 4 | （ビューポートの図面タイトル） | 図面タイトル |
| **`Drawing`** | 4 | `1`（シートレイヤ内で自動採番） | 図番 |
| `Sheet` | 4 | （シートレイヤ名） | シートレイヤ番号 |
| `BackRefSheetNo` | 4 | （空） | 逆参照シートレイヤ番号 |
| `ScaleDisplay` | 8 | `Architectural` | 縮尺表示 |
| `Custom Scale` | 4 | （空） | カスタム縮尺 |
| `LineMode` | 8 | `Auto-Fit` | ラベル幅モード |
| `Length` | 7 | `130` | 印刷時の線の長さ |
| `__Version` | 1 | `2600` | （表示名なし） |
| `__Edit Layout` | 14 | （空） | 図面ラベルレイアウト |
| `ControlPointX` | 7 | （実数） | （表示名なし） |
| `ControlPointY` | 7 | `0` | （表示名なし） |
| **`Link State`** | 1 | `0` / `1` | リンク状況 |
| `Note` | 4 | （空） | 備考 |
| `World-based` | 2 | `False` | `__NNA_DO_NOT_CHANGE` |

- 16 件の中に、図番・引出線の表示を切る真偽値の欄は無かった。`Length` を変えると
  タイトルの下線の長さが変わった。
- `Drawing`（図番）の値は作るたびに入っていた（下記「[図番（`Drawing`）の自動採番](#図番drawingの自動採番の実測179)」）。

## ラベルレイアウトの置き場所を探した

ラベル自身のプロファイルグループ（`ISDK::GetCustomObjectProfileGroup` /
`SetCustomObjectProfileGroup`）を読み書きした（[Data Tags](../Findings/Data%20Tags.md) のタグレイアウト・
[Level Objects](../Findings/Level%20Objects.md) のマーカーレイアウトと同じ手順）。

- `GetCustomObjectProfileGroupInAux` は `nil` を返した。
- 既定の中身（実測。型は `Objs.TDType.h`）:

```
レイアウト[0] 型=10（テキスト）'タイトル'
レイアウト[1] 型= 2（線）          ← タイトルの下線
レイアウト[2] 型=10（テキスト）'縮尺'
レイアウト[3] 型= 6（円弧）        ← 図番を囲む丸
レイアウト[4] 型=10（テキスト）'#'
レイアウト[5] 型= 0（終端）
```

- **テキストに名前は付いていない**（`GetObjectName` は空）。**レコードも付いていない。**
- ラベルの描いた図形を自分で走査すると、型 90（`kUndoPlaceholderNode`）が混ざることが
  あった。

## 動的な文字列の式の綴りと書き込む口を探した

レイアウトのテキストが持っている式（生バイトから UTF-16 で読み出した実測値）:

| 見えている文字 | 持っている式 |
| --- | --- |
| `タイトル` | **`#Drawing Label2#.#Title#`** |
| `縮尺` | `縮尺: #Drawing Label2#.#Scale#` |
| `#` | `#Drawing Label2#.#Drawing#` |

読み出した式は `#レコード#.#フィールド#` の形で、レコード名は PIO の universal 名、
フィールドはそのパラメータ名だった（調べる前は「図面ラベルは別の書き方になる」と見込んで
いた）。

- `#Drawing Label2#.#Scale#` の `Scale` は、上の 16 件には無い欄
  （レコードには在るが OIP に出ない計算欄）。
- 式が入っていたのは**テキストにぶら下がるユーザーデータ**（補助オブジェクト
  2 つ。型 **76** ＝ `kUserDataNode`。2 つ目の容れ物 ID が `'oidl'`）で、UTF-16 だった。
  `IDataTagTextLinkSupport` を呼んだ結果:

  | 呼んだもの | 結果 |
  | --- | --- |
  | `IsSupported(テキスト)` | **`false`** |
  | `GetIsLinked(テキスト)` | `false` |
  | `GetFormula(テキスト)` | **空文字列** |

- `IDataTagSupport::UpdateUserDefinedTextsUIDs` を呼ばずに組んだレイアウトが、図面タイトルを
  描いた。

## SDK から組んだ手順（複製して要らないものを落とす）

同じ図面で、渡すレイアウトを変えて描かれた文字を比べた:

| 渡したレイアウト | **描かれた文字** |
| --- | --- |
| 元のテキストを **`DuplicateObject` で複製**した 1 つだけ | **`アルファ図-書き換え後`**（＝`Title` の値） |
| 同じ文字列（`タイトル`）から **`CreateTextBlock` で新しく作った**テキスト 1 つだけ | **`タイトル`**（文字どおり。置き換わらない） |
| 複製したテキストの**文字を `SetText` で潰して**から渡す | **`手で書いた図面名`**（＝`Title` の値。**文字は無視される**） |

計測に使ったコード（タイトルのテキストと下線だけを複製して渡した）:

```cpp
MCObjectHandle hOld   = gSDK->GetCustomObjectProfileGroup(h);
MCObjectHandle hGroup = gSDK->CreateGroup(false);

// 例: タイトルのテキストと下線だけを残す（＝縮尺と図番を落とす）
bool tookText = false, tookLine = false;
for (MCObjectHandle m = gSDK->FirstMemberObj(hOld); m != nil; m = gSDK->NextObject(m))
{
	const short type = gSDK->GetObjectTypeN(m);
	if (!((type == kTextNode && !tookText) || (type == kLineNode && !tookLine)))
		continue;
	MCObjectHandle dup = gSDK->DuplicateObject(m);                  // ★ 複製して入れる
	gSDK->AddObjectToContainer(dup, hGroup);
	if (type == kTextNode)
	{
		// **文字の大きさを当てるのはここ。渡すのは「紙の上の mm」**
		// （容れ物の縮尺は VW が掛ける。下記「レイアウトの文字の大きさ」）。
		gSDK->SetTextSize(dup, 0, gSDK->GetTextLength(dup), 10.0 * 25.4 / 72.0);  // 紙で 10pt
		tookText = true;
	}
	else
		tookLine = true;
}

gSDK->SetCustomObjectProfileGroup(h, hGroup);   // **中身を入れてから渡す**
gSDK->ResetObject(h);
```

実測（タイトル＋下線の 2 つを複製した場合）:

```
渡した後のレイアウト: テキスト'タイトル' / 線 / 終端
描かれたもの        : テキスト'後から変えた題' / 線     ← 縮尺も図番も丸も消えた
```

## スタイルが当たる様子と外し方を試した

実機で測った（VW 2026 / mac・新規の空図面。`probes/runtime/drawing-label-style-textsize/`
を 7 回走らせた。[issue #175](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/175)）。

| 問い | 実測 |
| --- | --- |
| 新規の空図面のツールのスタイル | `GetPluginStyleForTool("Drawing Label2")` が **`ref=179`「図面ラベル - 図番」**を返した |
| **自動適用** | **する。** `CreateCustomObject` の**直後**に `GetPluginObjectStyle` が既にそれを返す |
| 別のスタイルでも同じ | 自分で作ったスタイル（`ref=119`）を `SetPluginStyleForTool` で設定してから作ると `ref=119` が当たった |
| 注釈へ入れて `ResetObject` | 当たったまま（変わらない） |
| **外し方①** | **`gSDK->SetPluginObjectStyle(h, 0)` は効く。** 戻り値 `true`・`ref=0` になり、**`ResetObject` も `UpdateViewport` も越えて残る** |
| **外し方②** | **`SetPluginStyleForTool(tool, 0)` にしてから作れば、最初からスタイル無しで生まれる。** 作った後にツールの値を元へ戻して `ResetObject` しても**当たり直さない** |

- `VWParametricObj::SetStyle(0)` を呼んだ: 実機で `ref` が 1 も動かなかった。実装
  （`SDKLib/Source/VWSDK/VWFC/VWObjects/VWParametricObj.cpp:1703`）は
  `InternalIndexToHandle(styleRefNumber)` の戻りが `nullptr` でないことを門にしている:

  ```cpp
  void VWParametricObj::SetStyle(RefNumber styleRefNumber) const
  {
      if(fhObject != nullptr)
      {	MCObjectHandle hStyle =  gSDK->InternalIndexToHandle( styleRefNumber );
          if(hStyle != nullptr && gSDK->IsPluginStyle( hStyle ))
          {	gSDK->SetPluginObjectStyle( fhObject, styleRefNumber );
          }
      }
  }
  ```

- `SDK Index` を総当りして、「スタイル無しにする」口として当たったのは `ConvertToUnstyledWall` /
  `ConvertToUnstyledSlab` / `ConvertToUnstyledRoof` の 3 つだけだった。

## 既定のレイアウトの持ち主とスタイルを外す順序の実測

スタイルの有無を変えて作り、レイアウトと絵を読んだ:

| | レイアウト（プロファイルグループ） | 絵 |
| --- | --- | --- |
| スタイル**有り**で作った直後 | `型 10 2 10 6 10 0` / テキスト 3 件（`6.0` `4.23333` `4.93889`） | 描く |
| スタイル**無し**で作った直後 | **`型 17 0`** / **テキスト 0 件** | **外接 0×0 ＝ 何も描かない** |
| 有りで作って、**組み直さずに**外した | `型 10 2 10 6 10 0`（**そのまま残る**） | 描く（外接 2834.9×846.9） |

- 外した後もレイアウトは残った（組み直したものも、既定のままのものも）。

## レイアウトの文字の大きさの実測

実機で測った。同じビューポートの注釈に「紙で 6pt になると分かっている寸法」
（`ovDimFontSize` ＝ `6 × 25.4/72 × 50` ＝ `105.83333`。[Dimensions](../Findings/Dimensions.md)）を
物差しとして置き、**注釈の中では紙の 1pt ＝ 世界座標 `17.63889`** と実測してから比べた。

レイアウトのテキストへ `SetTextSize` で与えた値と、描かれた文字:

| 置き場（容れ物） | 与えた値 | 描かれた文字（世界座標） | **紙の上** |
| --- | --- | --- | --- |
| ビューポートの注釈（1/50） | `3.52778` | `176.38889`（＝×50） | **10.00000pt** |
| ビューポートの注釈（1/50） | `176.38889`（縮尺を掛けてしまった） | `8819.44444` | **500pt** |
| ビューポートの注釈（**1/100** へ変更） | `3.52778` | `352.77778`（＝×100） | **10.00000pt** |
| デザインレイヤ（1/50） | `3.52778` | `176.38889`（＝×50） | **10.00000pt** |
| シートレイヤ直下（1:1） | `3.52778` | `3.52778`（＝×1） | **10.00000pt** |

- `ISDK::SetTextSize` へ `10` を渡すと **10mm ＝ 28.3pt** で描かれた。同じ図の 6pt の
  寸法（2.1167mm）と比べて 4.7 倍で、[#175](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/175)
  の発端（「10pt を与えたのに 4 倍前後大きい」）はこれだった。
- 容れ物とアクティブレイヤを**交差させて**測った——デザインレイヤ(1/50) に置いて
  アクティブ 1:1 でも紙で 10pt、シートレイヤ(1:1) に置いてアクティブ 1/50 でも紙で 10pt。
  注釈でも、アクティブ 1/50 で掛からなかった回とアクティブ 1:1 で掛かった回の両方がある。
- 組み直しの時機（注釈へ入れる前／後）を入れ替えて測った 2 つの走行で、読み戻した値・
  外接ともに**完全に同値**だった。比べたのはどちらも縮尺が掛かっていない側の状態
  （#177 の読み違いの走行。下記【訂正の記録】）。確定している走行はすべて「先に組んで
  から入れる」順である。
- ビューポートの縮尺を 1/50 → 1/100 へ後から変えると、描かれた文字が `176.389` →
  `352.778` になった（紙の上は 10pt のまま）。
- `ScaleFactor`（記号の倍率）を 2 にすると紙で 20pt になった。
- `World-based`=True は文字の大きさを変えなかった（同じ容れ物で `False` と完全に同値）。
- 既定のタイトルの大きさは **`6.0`**（紙で 6mm ＝ 約 17pt）。

### 文字スタイル（`SetTextStyleRef`）を当てるときのアクティブレイヤの縮尺の実測

レイアウトのテキストへ文字スタイルを当てた直後の大きさ:

| 当てたときのアクティブレイヤ | 10pt（`ovTextStyleSize` ＝ `0.13889` インチ）を当てた直後の `GetTextSize` |
| --- | --- |
| デザインレイヤ 1/50 | **`176.38889`**（＝ 3.52778 × 50） |
| シートレイヤ 1:1 | **`3.52778`** |

1/50 のレイヤをアクティブにしたまま当てたラベルは、紙で 500pt で描かれた。1:1 の
レイヤをアクティブにしてから当てると、`SetTextSize` と同じ結果になった。

## ビューポートとの紐づき

ヘッダ（`Kernel/API/ObjectVariables.h`）の抜き書き:

```
const short ovViewportDescription = 1032;  // … corresponds to the Dwg Title field for a
                                           //   corresponding Drawing Label.
const short ovViewportLocator     = 1033;  // … corresponds to the Item field for a
                                           //   corresponding Drawing Label.
```

実測した挙動:

| 置いた場所 | `Link State` | ビューポートのタイトルを変えたとき |
| --- | --- | --- |
| **ビューポートの注釈** | **`1`** | **追随する**（ホストのビューポートの値が入る） |
| シートレイヤ直下 | `0` | 追随しない |

- 図面タイトルの違う 2 枚を並べ、2 枚目の注釈に置いたラベルで 2 枚目のタイトルを
  書き換えたら、そのラベルが追随した。
- 2 枚目の注釈へ置いたラベルに、置いた直後は 1 枚目のタイトルが入っていた（その図面で
  いちばん最初のラベルでも同じ。理由は下記「生まれたときの `Title` の出どころ…」の #249 で測った）。
- `SetParamValue("Title", …)` は `Link State` が 0 でも 1 でも値が入り、描く文字も変わった。
- 手で `手で書いた題` を書いた注釈のラベルが、ビューポートの 1032 を変えた後は
  `後から変えた題` になった。
- 作りたてのビューポートで `GetViewportGroup(vp, kViewportGroupAnnotation)` が `nil` を
  返した（そちらから入れようとして 1 往復無駄にした）。`ISDK::AddViewportAnnotationObject`
  で入れた後は `GetViewportGroup` も取れ、`VWViewportObj::IsViewportGroupContainedObject` も
  `true` を返した。
- `CreateViewport` で作ったビューポートは**全クラスが非表示**のまま生まれ（[Viewports](../Findings/Viewports.md)
  「クラス表示」）、その注釈へ置いたラベルは、文字を生成していても（外接
  `GetObjectBounds` が `0` でなくても）クラス表示を戻すまで画面に出なかった。

### 1 つのビューポートの注釈に図面ラベルを複数置いたときの VW の警告

**複数置いた注釈を開くと、VectorWorks が警告ダイアログを出す**（#177 の実機確認で遭遇。
VW 2026 / mac・日本語版。1 つの注釈へ 4〜5 本置いた図面で、注釈の編集画面を開いたとき）:

> このビューポートの注記グループには複数の図面ラベルがあります。
> 自動作図調整は、1 つのビューポートに複数の図面ラベルがあると正常に機能しません。

- 複数置く途中の `AddViewportAnnotationObject` はどれも `true` を返し、絵も出た。
- 複数本入れた注釈での図番は下記「[図番（`Drawing`）の自動採番](#図番drawingの自動採番の実測179)」で測った。
- 下記の `Title` の測定は、1 ビューポート 1 ラベルの置き方で測り直しても同じ結果だった
  （下記「測り直し」）。

### 置いたときに流れる向きの実測（#177）

新規の空図面で、**ビューポートの 1032 を入れてある / 入れていない**の 2 通りを並べ、
注釈へ置く前後の `Title` と 1032 を読んだ（VW 2026 / mac）:

| 置く前の 1032 | 置くときに `Title` を書いたか | 置いた後のラベルの `Title` | **置いた後の 1032** |
| --- | --- | --- | --- |
| `VP2 の図面タイトル` | 書かない | **空のまま** | **空になった**（＝ラベルが潰した） |
| 空 | 書かない | 空のまま | 空のまま |
| 空 | **書いた**（`調査用の図面タイトル`） | `調査用の図面タイトル` | **`調査用の図面タイトル`**（＝ラベルが入れた） |

- 上の表のラベルは、どれも空の `Title` で生まれていた。題を持って生まれたラベルを
  置いたときは、その題がビューポートの 1032 へ入った（すぐ下）。

### 生まれたときの `Title` の出どころの実測（#249）

実機で測った（VW 2026 / mac。[#249](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/249)。`probes/runtime/t0-mismatch`。
既定のテンプレート `Default.sta` から開いた図面と、`OpenDocumentPath(nullptr)` の空の図面）。
`CreateCustomObject("Drawing Label2", …)` した直後（注釈へ入れる前）の `Title` を、
選択とアクティブレイヤを振って読んだ。

| 作った瞬間の状態 | 生まれたときの `Title` |
| --- | --- |
| ビューポートが 1 枚も無い | 空 |
| `CreateViewport` で題 `A` の VP を作った直後 | **`A`** |
| 続けて題 `B` の VP を作った直後（A・B とも選択されたまま） | **`A`** |
| A の 1032 を `A2` へ書き換えた後 | **`A2`**（その場で読んでいる） |
| `DeselectAll()` の後 | **空** |
| B だけを選択 | **`B`** |
| A と B を選択（選んだ順はどちらでも） | `A`（並びの先のもの） |
| ビューポートでない矩形だけを選択 | 空 |
| 空の VP を選択 | 空 |
| VP の無い別のシートがアクティブ | 空 |
| 別のシートに C を作った直後（そこがアクティブ） | `C` |
| 元のシートへ戻った（そこの VP は選択されていない） | 空 |
| デザインレイヤがアクティブ（B を選択したまま） | **文書名**（`名称未設定 26` など） |
| 前のラベル（注釈へ入れていない）に `Title` を書いた後・VP の選択無し | 空（**前のラベルからは引き継がない**） |
| 置く位置（選択中の VP の上／遠く） | 変わらない |

- `CreateViewport` の後の選択を読むと、作ったビューポートが選択されたまま残り、それまでの
  選択も外れていなかった（A を作った直後に A が選択、B を作った直後に A・B とも選択）。

## `Title` が空のラベルの描画の実測（#177）

新規の空図面・1/50 のビューポートの注釈で、レイアウトのテキストへ `3.52778`（紙で 10pt）を
与えて測った実測（VW 2026 / mac。**ラベル 11 本**）:

| `Title` | ラベル自身の外接 | ラベルが描いた文字 |
| --- | --- | --- |
| 空 | 幅 `238.12500` **高 `0.00000`**（＝下線だけ） | **無し** |
| `調査用の図面タイトル` | 幅 `1998.48608` 高 `264.58333` | 大きさ `176.38889` ＝ **紙で `10.00000pt`** |

- 同じビューポートへ `Title` を書かずに 4 本続けて置き、他の 3 枚のビューポートへ置き
  終えた後にもう 1 本（5 本目）を足しても、5 本とも文字は出なかった。
- 1032 に値を入れてから作ったビューポートでも、`Title` を書かなければ同じく出なかった
  （上表「置いたときに流れる向き…」。このときラベルを作った瞬間にそのビューポートは
  選択されていなかった——上記「生まれたときの `Title` の出どころ…」。#249）。
- 容れ物を 4 通りに振っても（作りたて／同じ注釈へ 4 本置いた後／図面タイトルを入れて
  ある／他の 3 枚を使い終えた後）、結果は `Title` だけで分かれた。
- `SetPluginObjectStyle(h, 0)` を挟んだ組と挟まない組でも、結果は `Title` だけで分かれた。
- `Title` を書いたラベルは、注釈の 1 本目から `3.52778 × 50 = 176.38889`（＝紙で 10pt）で
  描かれた（[#175](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/175)
  の表と同じ）。

> **【訂正の記録】** [#177](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/177)
> では最初、「作りたてのビューポートの注釈では、先頭の 1〜2 本が容れ物の縮尺を拾わない」
> と読んだ。測り直すと、その本は文字を 1 つも描いていなかった（`Title` が空）。
> ラベルの木を `FirstMemberObj` で辿ると、描いた図形だけでなく**レイアウト（プロファイル
> グループ）も一緒に拾い**、そこには「レイアウトへ与えた値」がそのまま（`3.52778`）入って
> いた。文字が出ているラベルではテキストが 2 件（レイアウトの `3.52778` ＋ 描いた
> `176.38889`）並び、出ていないラベルでは 1 件（`3.52778`）だった。大きさ `3.52778` の文字が
> 本当に描かれていれば外接の高さは `5.29167`（＝×1.5）になるが、測った外接の高さは `0`
> だった。一般化した形は [調査の作法](../Findings/Investigation%20Techniques.md)「描かれている
> 文字を測る」。

### 測り直し——「描くまで計算が遅れていたのでは」を確かめた

最初の実測は**全クラス非表示のビューポート**（`CreateViewport` の既定）で行ったので、
**一度も絵になっていない状態**を測っていた（描画まで計算が遅れているかを切り分けるため）。
クラスを全部表示へ戻して `UpdateViewport` で実際に描かせ、**同じラベルを 2 度**
（`ResetObject` の直後と、描かせた後）測った。置き方は 1 ビューポート 1 ラベル。

| | `Title` | 【1 段目】`ResetObject` の直後 | 【2 段目】描かせた後 |
| --- | --- | --- | --- |
| VP-A | 空 | 外接 幅 `238.12500` 高 `0.00000` / 描いた文字 **無し** | **まったく同じ** |
| VP-B | `調査用の図面タイトル` | 外接 幅 `1998.48608` 高 `264.58333` / 文字 `176.38889` | **まったく同じ** |

- 1 段目と 2 段目が 1 桁も動かなかった。
- `Title` も動かなかった（VP-A は空のまま、VP-B は書いた値のまま）。
- ビューポートの 1032 も描画で変わらなかった（VP-A は空、VP-B は書いた値）。
- 最初の実測でも、同じ「描かれていない」ビューポートの中で、`Title` を書いた腕は
  縮尺まで掛かった `176.38889` の文字を持っていた。
- 上の 2 段は**どちらも同じ呼び出しの中**で測った（`UpdateViewport` は戻った時点で
  描き終わっていない——[Viewports](../Findings/Viewports.md)）。そこで **undo イベントを閉じた後と、
  VW へ戻って数十秒置いた後**にも読み直した（[#245](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/245)。既定のテンプレートから開いた
  図面・1/50 の平面ビューポート 3 枚に 1 本ずつ）。ラベルの `Title`・`LinkState`・外接・
  描いた文字（`176.38889`）とビューポートの 1032 は、**3 時点とも 1 桁も変わらなかった**。
  - この回は、空の `Title` のラベルが 1032 を消す（上の「置いたときに流れる向き…」）が
    書いた直後の時点で再現しなかった。この回は題を入れたビューポートを最初に作っていて、
    それが選択されたまま残り、後のラベルがみなその題を持って生まれていた
    （[#249](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/249)。上記「生まれたときの `Title` の出どころの実測」）。
