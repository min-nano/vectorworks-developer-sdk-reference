# レイヤの中のオブジェクトの列挙と数え方 — 計測記録

結論は [Findings「Layer Objects」](../Findings/Layer%20Objects.md)。ここには測った環境・見本・
実測の表と、Windows の VM で落ち続けた切り分けを置く。

[issue #282](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/282) の調査。
[vectorworks-plugin-command-line-interface](https://github.com/min-nano/vectorworks-plugin-command-line-interface)
の `layer_objects` / `object_counts` / `layers` の `objects` のため、レイヤの中の図形を
どう辿り、どう数え、何を読めるかを測った。

## 測った環境と手順

- **Windows**: VW 2026 Update 6（Build 872399）・Windows 11 Pro ARM64 の VM（UTM）の x64
  エミュレーション・描画は WARP。2026-11-03。1〜3・5〜8 の数。
- **mac**: VW 2026（31.6.0、Build 872399）・macOS 27.0.1・arm64。2026-11-04。同じ見本で同じ数を
  確かめ、**画面との突き合わせ・重ね順・消した / 取り消した図形はこちらで測った**（Windows の VM
  は画面の操作で落ち続けたため。[下記](#windows-の-vm-では描画のスレッドで落ち続けた)）。

どちらも `probes/runtime/layer-objects/`（役目を終えたので消してある）をブリッジ
（`vw_run_probe`）から新規の空図面で走らせた。mac の画面の操作は、メニューの「編集」「加工」
「ファイル」を押して、情報パレットとオーガナイザを読んだ。

**見本**（プローブが自分で作る。プローブは undo イベントを開かない）:

| レイヤ | 中身 |
| --- | --- |
| `LO-A`（デザイン・1:1） | 直線（名前あり）・矩形（名前なし・クラス `LO-クラス`）・30° 回した矩形・楕円・文字・グループ（直線 2 ＋入れ子のグループ（矩形 1））・シンボル 2（0° と 45°。定義に矩形 2）・ドア（PIO）・壁・押し出し（矩形 1） |
| `LO-B`（デザイン・1:50） | `LO-A` の矩形と同じ座標の矩形 1・文字 2（mac のみ） |
| `LO-多`（デザイン・1:1） | 矩形 3000 |
| `LO-S`（シート） | ビューポート 1（`LO-A` を映す） |

## 1. 辿る順

列の 3 番目の `LO-回転` に、mac で「加工 > 前後関係」を掛けた:

| 操作 | `LO-回転` の位置 | 元の位置 |
| --- | --- | --- |
| 最前へ | **末尾**（終端の直前）へ移った。番地は変わらない | 型 `90` の置き石が残った |
| 最後へ | **先頭**へ移った | 末尾に型 `90` の置き石が残った |

- `FirstMemberObj` → `NextObject` と `LastMemberObj` → `PrevObject` の逆順は毎回一致した。
  `ForEachObjectN` が渡す順とも、図形でないものを除いて全件一致（`traverseWhat` を変えても同じ）。
- レイヤの並び（mac）: `GetDrawingHeader` の子は `レイヤ-1` → `LO-A` → `LO-B` → `LO-多` →
  `LO-S` の順。オーガナイザの `#` は `LO-多` 1・`LO-B` 2・`LO-A` 3・`レイヤ-1` 4。

## 2. 列に混ざる、図形でないもの

- 終端（型 `0`）は空のレイヤでも 1 つあった。
- 置き石（型 `90`）: 名前は空、`GetObjectBounds` は `false`、親は `31`（レイヤ）。見本を作った
  直後には無く、並べ替え・消去・複製の取り消しのたびに増えた（[下記 4](#4-消した図形取り消した図形mac)）。
  壁の子にも出たことがある（Windows）。
- `kMarkedForRemoval = -128` の型は、消した図形でも取り消した図形でも出なかった（mac）。

## 3. 入れ子と `ForEachObjectN` の `traverseWhat`

`LO-A` の数（終端を除く。**Windows と mac で同じ値**）:

| 辿り方 | `LO-A` の数 | 中身 |
| --- | --- | --- |
| `FirstMemberObj` → `NextObject` | 11 | 直下だけ |
| `ForEachObjectN(allDrawing = 3)` / `allObjects = 6` | 11 | 直下だけ。並びも同じ |
| `+ descendIntoGroups (32)` | 15 | **グループの中だけ**入る（直線 2・入れ子のグループ・その矩形） |
| `+ descendIntoAll (64)` | 72 | グループに加えて **PIO（ドアの子）・壁の子・押し出しの子にも入る** |
| `+ descendIntoViewports (128)` | 72 | 変わらない（ビューポートの中には入らなかった） |
| `+ descendIntoAuxLists (256)` | 11 | レイヤの数は変わらず、**レイヤ外に 6000 余りの内部の記録**（型 76 が大半）が増える |

- `allObjects` はレイヤ外にシンボル定義（とその中身）を 3 件足した。`allObjectsAndResources = 7`
  は更に資源（クラス定義 `94` など）を 40 件ほど足した。
- `allSelected = 0` / `allEditable = 1`（mac）: `LO-A` がアクティブで 1 つ選んでいるとき 1 と 11。
- `allVisible = 2`（mac）: アクティブが `LO-A` のときはデザインレイヤ 3 枚の 3012 件（レイヤ
  オプションは「ほかをグレイ表示/スナップ」）、アクティブがシートレイヤ `LO-S` のときはその 2 件。
- `NumSelectedObjects`（mac）: 別のレイヤにも選択された図形があるのに、`LO-S` のとき 2、`LO-A`
  のとき 11 を返した。
- 作った直後の図形は `IsSelected` が真だった（入れ子の中も）。

**画面の数との対応**:

| 画面 | 表示 | プローブの数 |
| --- | --- | --- |
| 情報パレット。`LO-A` で「すべてを選択」 | **11 図形** | `FirstMemberObj` → `NextObject` から `0` と `90` を除いた数・`allDrawing` の `LO-A` の数・`NumSelectedObjects` |
| 情報パレット。置き石が 2 つある `LO-A` で「すべてを選択」 | **11 図形** | 同上（列を素直に数えると 13 のノード＋終端） |
| 情報パレット。シートレイヤ `LO-S`（Windows・mac） | **2 図形** | `allSelected` の 2（ビューポートと、下記 7 の窓） |
| オーガナイザ「デザインレイヤ」の全列（窓を広げて右端まで見た） | **図形の数の列は無い** | `#`・縮尺・ストーリ・ストーリレベル・高さ・壁の高さ・GIS・タグ・切断面の高さ・カラー・不透明度・背景テクスチャ |

- 情報パレットは SDK からアクティブレイヤを替えただけでは更新されなかった（`LO-A` へ替えて選択が
  11 件のときも「2 図形」のままで、「すべてを選択」で「11 図形」に変わった。mac）。

## 4. 消した図形・取り消した図形（mac）

| 操作（`LO-A`） | 列（終端を除く） | うち型 `90` | `allDrawing` の `LO-A` |
| --- | --- | --- | --- |
| 見本を作った直後 | 11 | 0 | 11 |
| 最前へ | 12 | 1 | 11 |
| 最後へ | 13 | 2 | 11 |
| `LO-直線` を消去 | 13 | **3**（直線が同じ位置で置き石に替わる） | **10** |
| その消去を取り消し | 13 | 2（直線が同じ位置に戻る） | 11 |
| `LO-文字` を複製 | 14 | 2（末尾に `LO-文字-2`） | 12 |
| その複製を取り消し | 14 | **3**（`LO-文字-2` が同じ位置で置き石に替わる） | **11** |
| 続けて保存（ブリッジの別名保存。もう 1 周でも同じ） | 13 | **2**（複製を取り消した置き石だけ消える） | 11 |
| `LO-直線` を消去して「ファイル > 保存」 | 13 | **3**（**消去の置き石は保存しても残る**） | 10 |

- `GetNamedObject("LO-直線")` は消去の後は nil、取り消した後は戻った図形を返した。
- 消去を取り消して戻った図形の番地: `0x7c0341b980` → `0x7bfa9b0140`。並べ替えでは番地は
  変わらなかった。
- ブリッジの別名保存を挟んでも、メニューの「取り消し」は 1 段で消去や複製を戻した。空の段を積むのは
  図面に PIO を初めて足したあとの最初の保存だけで、見本を作った回のブリッジの保存で使い切っていた
  ためと読める【推定】（#288。[Undo](../Findings/Undo.md)）。

## 5. 種別の名前

見本で出た `GetObjectTypeN` の番号: `2` 直線・`3` 矩形・`4` 楕円・`10` 文字・`11` グループ・
`15` シンボル・`16` シンボル定義・`24` 押し出し・`68` 壁・`86` PIO・`122` ビューポート（ほかに
子として `5` 多角形・`6` 円弧・`17` 点・`21` ポリライン・`84` CSG）。番号の一覧は
`Objs.TDType.h`（`kLineNode = 2` 〜 `kWallStyleNode = 127`）。

## 6. 名前・クラス・外形

- `ClassIDToName` で引けたクラス名: `"一般"`・`"LO-クラス"`。PIO の子には `"非出力"` もあった。
  置き石（型 90）は空。
- 複製の名前: `LO-文字` → `LO-文字-2`。
- 1:1 の `LO-A` と 1:50 の `LO-B` に同じ座標で作った矩形は、同じ `[0,100 → 1000,600]` を返した。
- 30° 回した 1000×500 の矩形は `[1250,100 → 2366.025,1033.013]`。
- 文字（mac。同じ文字列・既定の書体）:

  | 文字 | 幅 × 高さ（mm） |
  | --- | --- |
  | `LO-A`（1:1）へ、1:1 のシートレイヤで作って移した | 21.251 × 6.350（Windows は 21.251 × 4.233） |
  | `LO-B`（1:50）をアクティブにして作った | **1062.567 × 317.500**（ちょうど 50 倍） |
  | 1:1 のシートレイヤで作って `LO-B` へ `AddObjectToContainer` で移した | **21.251 × 6.350**（**1:50 のレイヤにあるのに 1:1 のまま**） |

  - 移した文字が描き直しで大きさを変えるかは測っていない（`ResetObject` も掛けていない）。
- `GetObjectCube` の Z: 押し出し `0 → 1000`・ドア `0 → 2093`。
- シートレイヤのビューポートの外形: mac は `[-43.065 → 43.065]`、Windows は `[-34.9 → 34.9]` 前後。

## 7. シートレイヤ

- シートレイヤを辿ると、ビューポート（型 `122`、名前 `"Viewport-1"`）と終端だけが出た（窓を除く）。
- アクティブがシートレイヤのときに壁の上の位置で `CreateCustomObject` で窓を作ると、窓はシート
  レイヤに置かれ、デザインレイヤの壁には入らなかった（Windows・mac）。作ったあとに
  `AddObjectToContainer(窓, 壁)` を呼ぶと `true` が返るのに、窓の親が nil になった（Windows）。

## 8. 刻みの中の所要

ブリッジの要求は刻みの中で処理される（mac は `CFRunLoopTimer`、Windows は `SetTimer`）。
「`SetTimer` の刻みの中」は、プローブの中で回したメッセージループから受けた別の刻み。

`LO-多`（矩形 3000）を、名前・外形・クラスを読みながら `FirstMemberObj` → `NextObject` で辿った
所要:

| | 1 回目 | 2 回目 | 3 回目 |
| --- | --- | --- | --- |
| Windows。ブリッジの要求の中 | 5.4 ms | 6.4 ms | 5.7 ms |
| Windows。`SetTimer` の刻みの中 | 8.4 ms | 5.3 ms | 7.3 ms |
| Windows。`SetTimer` の刻みの中の `ForEachObjectN(allObjects)`（全図面 3016 件を数えるだけ） | 2.0 ms | 0.7 ms | 1.0 ms |
| mac。ブリッジの要求の中 | 0.68 ms | 0.50 ms | 0.49 ms |
| mac。ブリッジの要求の中の `ForEachObjectN(allObjects)`（全図面 3017 件。レイヤごとの集計つき） | 1.13 ms | — | — |

## Windows の VM では描画のスレッドで落ち続けた

見本を作ったあとの画面の操作で、**VW が 7 回落ちた**（`0xc0000005`・番地 0 の実行）。
WER のダンプを読むと、**落ちたスレッドには `d3d10warp.dll`（Windows のソフトウェア描画）の
番地しか無く、VW 本体・プラグインのコードは無かった**。主スレッドは待ちの中。
[Viewports](../Findings/Viewports.md)（#248）・[Plug-in Modules](../Findings/Plug-in%20Modules.md) にある、
この VM の描画の側の落ちと同じ形である。

中身を変えて切り分けた（見本を作り、アクティブレイヤを `LO-S` から `LO-A` へ切り替える）:

| 作ったもの | 結果 |
| --- | --- |
| レイヤだけ（図形なし） | 落ちない |
| 矩形 3000（`LO-多`） | 落ちない |
| シンボルだけ | 落ちた |
| 2D ＋シンボル | 落ちた |
| シンボル抜きの全部（2D・ドア・壁・押し出し・ビューポートなど） | 落ちた |
| **人がメニューで作ったシンボル**（プローブの図形なし・レイヤ切り替えもなし。「シンボル登録」の直後） | **落ちた** |

- 同じ時刻に Windows のサービス（`webthreatdefsvc`）も落ちていた。
- mac では、同じ見本でアクティブレイヤの切り替え・選択・並べ替え・消去・複製・取り消し・保存の
  どれでも落ちなかった。
- Windows の 1〜3・5〜8 の値は、落ちる前にプローブが成功で返したログであり、落ちとは関係しない。
