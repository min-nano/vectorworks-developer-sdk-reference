# スラブ・押し出し

## スラブ・壁の構成層

- **スタイルを作らず、unstyled のスラブ／壁へ構成層と基準面を直接与えられる**
  （`ConvertToUnstyledSlab` / `ConvertToUnstyledWall` してから設定する）。スタイルを作る形は、
  処理のたびに名前付きリソースが増え、しかも undo で消えない。
- **厚み 0 の構成層は VW が受け付けない。** 余った層は 0 に潰さず**削除**する。
- **構成要素は素材ごとのクラスに分け、層の描画属性はクラス属性に従わせられる**
  （`SetComponentClass` ＋ `SetComponentUseFillClassAttr` / `…UsePenClassAttr`）。
  オブジェクト本体のクラス（その部材が何か）とは別の軸で、**層が何でできているか**を表せる。
- 構成層は「一様な厚みの水平な層」しか表せない。深さが場所で変わるもの・法線方向に厚みを
  持つものは押し出しソリッドで描くしかない。

## `VWExtrudeObj` の平行移動

**`VWExtrudeObj` は押し出しを「2D 基面 ＋ 基準高さ ＋ 厚み」に持ち替える。** そのため 3D
ポリゴンから作ると基面の平面を導出したうえで**配置先レイヤの高さを法線方向へ足す**。
普通の押し出しは鉛直なのでこれは正しい動作だが、**水平押し出しではそのまま
軸方向の横ずれになる**（実測: 指定どおりの長さ 11905 のまま、位置だけ +50mm＝レイヤ高さ）。
対処は**置いた後に `GetObjectBounds` で実位置を測り、`MoveObject3D` で寄せ直す**。
レイヤ高さを当てにいかず実測で補正すれば、VW 側の挙動が変わってもそのまま正しい。

- 押し出しは**基面の法線方向へ伸びる**ので、頂点の並びを法線が伸ばしたい向きを指すよう
  揃える（Newell 法）。

## 打ち切った調査: スラブへ「足す」噛み合わせ（`ModifySlab`）

**結論: SDK からは実現できない（VW 2026）。** 削り取りモディファイアと可視ソリッドを
**2 回作る**のが最善。

SDK には専用の API がある——`ISDK::ModifySlab(slab, modifier, isClipObject, componentFlags)`
（説明は "Adds to or clips from a slab."）。API の形の上では `isClipObject = false` が
「足す」に当たる。

- しかし**実機（VW 2026）では「選択が間違っています」のダイアログを出して false を返す**。
  スラブは元のまま・モディファイアにしたい図形も独立したまま残り、ダイアログは呼んだ
  回数ぶん出る。
- 「全解除 → スラブと図形だけを選択 → 呼ぶ」も試したが結果は同じ。引数のハンドルの問題でも
  選択状態の問題でもなく、**VW 側の不具合の可能性が高い**。
- スラブのモディファイアを扱う API は `ModifySlab` だけで、他の手段は無い。
- **UI 産物を解析した結果**（同じスラブに SDK の削り取りと UI の噛み合わせが同居する状態を
  ダンプで覗いた）:

  | | SDK の削り取り | UI の噛み合わせ |
  | --- | --- | --- |
  | 押し出しの補助オブジェクト | `type=114` ＋ `DMDT`×3 | `type=114` ＋ **`type=121`** ＋ **`OPhI`** ＋ `DMDT`×4 |

  構造そのものは同じ（スラブのプロファイル群に押し出しが入るだけ）で、**違いは押し出しに
  付く補助オブジェクト**。しかも**スラブ本体にも同じ組が付く**（両側にリンクが張られる）。
- **この 2 つは SDK からは作れない。** `NewDataObject` が作れるのはデータオブジェクト
  （`type=76`）だけで、`type=121` のノードを作る API は無い。`OPhI` / `DMDT` などのタグは
  **SDK ヘッダのどこにも定義が無い**（VW 内部専用）ため中身のバイト列も分からない。
- UI でできるのに API でできないのは VW 側の不具合か未公開機能なので、筋としては
  Nemetschek へ報告して `ModifySlab` の修正を待つ。
