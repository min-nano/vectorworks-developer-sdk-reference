# レイヤの中のオブジェクトの列挙と数え方

[issue #282](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/282) の調査。
[vectorworks-plugin-command-line-interface](https://github.com/min-nano/vectorworks-plugin-command-line-interface)
の `layer_objects` / `object_counts` / `layers` の `objects` のため、レイヤの中の図形を
どう辿り、どう数え、何を読めるかを測った。

**測った環境**:

- **Windows**: VW 2026 Update 6（Build 872399）・Windows 11 Pro ARM64 の VM（UTM）の x64
  エミュレーション・描画は WARP。2026-11-03。1〜3・5〜8 の数。
- **mac**: VW 2026（31.6.0、Build 872399）・macOS 27.0.1・arm64。2026-11-04。同じ見本で同じ数を
  確かめ、**画面との突き合わせ・重ね順・消した / 取り消した図形はこちらで測った**（Windows の VM
  は画面の操作で落ち続けたため。[下記](#windows-の-vm-では描画のスレッドで落ち続けた)）。

どちらも `probes/runtime/layer-objects/`（役目を終えたので消してある）をブリッジ
（`vw_run_probe`）から新規の空図面で走らせた。mac の画面の操作は、メニューの「編集」「加工」
「ファイル」を押して、情報パレットとオーガナイザを読んだ。

**見本**（プローブが自分で作る。プローブは undo イベントを開かない）:

| レイヤ | 中身 |
| --- | --- |
| `LO-A`（デザイン・1:1） | 直線（名前あり）・矩形（名前なし・クラス `LO-クラス`）・30° 回した矩形・楕円・文字・グループ（直線 2 ＋入れ子のグループ（矩形 1））・シンボル 2（0° と 45°。定義に矩形 2）・ドア（PIO）・壁・押し出し（矩形 1） |
| `LO-B`（デザイン・1:50） | `LO-A` の矩形と同じ座標の矩形 1・文字 2（mac のみ） |
| `LO-多`（デザイン・1:1） | 矩形 3000 |
| `LO-S`（シート） | ビューポート 1（`LO-A` を映す） |

## まとめ: 画面の数に合わせて数える手順

- **情報パレットの「N 図形」に合うのは、レイヤの直下の図形の数**（グループ・シンボル・PIO・壁は
  中身を数えず 1 つ。`LO-A` で 11）。**オーガナイザには図形の数の列が無い**（下記 3）。
- **`FirstMemberObj` → `NextObject` で辿るなら、型 `0`（終端）と型 `90`
  （`kUndoPlaceholderNode`）を除く。** 除かないと、操作の履歴がある図面で多く出る（下記 2・4）。
- **`ForEachObjectN(allDrawing, …)` なら、どちらも渡されない**ので除かなくてよい。ただしレイヤごとに
  分けるなら `ParentObject` で分ける。シートレイヤの図形も混ざる（下記 7）。
- 列の並びは**先頭が最背面・末尾が最前面**（下記 1）。

## 1. 辿る順

- **`FirstMemberObj(layer)` → `NextObject` の順は、作った順と同じ。** 先頭が最初に作ったもの、
  末尾（終端の 1 つ手前）が最後に作ったもの。
- **`LastMemberObj(layer)` → `PrevObject` は、そのちょうど逆**（毎回一致）。
- **`ForEachObjectN` がレイヤの直下の図形を渡す順も、`FirstMemberObj` → `NextObject` と同じ**
  （図形でないものを除いて全件一致。`traverseWhat` を変えても同じ）。
- **先頭が最背面・末尾が最前面。** 列の 3 番目の `LO-回転` に、mac で「加工 > 前後関係」を掛けた:

  | 操作 | `LO-回転` の位置 | 元の位置 |
  | --- | --- | --- |
  | 最前へ | **末尾**（終端の直前）へ移った。番地は変わらない | 型 `90` の置き石が残った |
  | 最後へ | **先頭**へ移った | 末尾に型 `90` の置き石が残った |

- **レイヤの並びも同じ向き**（mac）。`GetDrawingHeader` の子は `レイヤ-1` → `LO-A` → `LO-B` →
  `LO-多` → `LO-S` の順で、オーガナイザの `#` は `LO-多` 1・`LO-B` 2・`LO-A` 3・`レイヤ-1` 4。
  デザインレイヤについて `#` の逆順に並ぶ。シートレイヤも同じ列の中にある。

## 2. 列に混ざる、図形でないもの

- **終端（`kTermNode` = 型 `0`）が各レイヤの列の末尾に 1 つ入る**（[Dimensions](Dimensions.md)
  の既知のとおり）。空のレイヤでも 1 つある。**数えるときは除く。**
- **undo の置き石（`kUndoPlaceholderNode` = 型 `90`）がレイヤの直下にも入る**（mac）。見本を
  作った直後の図面には無いが、**並べ替え・消去・複製の取り消しのたびに増える**（下記 4）。名前は
  空、`GetObjectBounds` は `false`、親は `31`（レイヤ）。**数えるときは除く。**
  - 中まで辿るときも同じ（[Parametric Objects](Parametric%20Objects.md) の置き石と同じもの。
    壁の子にも出たことがある。Windows）。
- **`kMarkedForRemoval = -128` という型の値がヘッダにある**【ヘッダ根拠】が、**消した図形でも
  取り消した図形でも、この型では出なかった**（mac）。

## 3. 入れ子と `ForEachObjectN` の `traverseWhat`

`LO-A` の数（終端を除く。**Windows と mac で同じ値**）:

| 辿り方 | `LO-A` の数 | 中身 |
| --- | --- | --- |
| `FirstMemberObj` → `NextObject` | 11 | 直下だけ |
| `ForEachObjectN(allDrawing = 3)` / `allObjects = 6` | 11 | 直下だけ。並びも同じ |
| `+ descendIntoGroups (32)` | 15 | **グループの中だけ**入る（直線 2・入れ子のグループ・その矩形） |
| `+ descendIntoAll (64)` | 72 | グループに加えて **PIO（ドアの子）・壁の子・押し出しの子にも入る** |
| `+ descendIntoViewports (128)` | 72 | 変わらない（ビューポートの中には入らなかった） |
| `+ descendIntoAuxLists (256)` | 11 | レイヤの数は変わらず、**レイヤ外に 6000 余りの内部の記録**（型 76 が大半）が増える |

- **シンボルのインスタンスは子を持たない**（`FirstMemberObj` が nil）。中身は定義（型 `16`）に
  あり、**定義はどのレイヤにも属さない**。`descendIntoAll` でもインスタンスの中には入らない。
- **`allObjects` は `allDrawing` にシンボル定義（とその中身）を足す**（レイヤ外に 3 件）。
  `allObjectsAndResources = 7` は更に資源（クラス定義 `94` など）を 40 件ほど足す。
- **`allSelected = 0` / `allEditable = 1` はアクティブレイヤの図形しか渡さない。**
  `allSelected` はそのうちの選択されたものだけ、`allEditable` は全部（mac。`LO-A` がアクティブで
  1 つ選んでいるとき 1 と 11）。**図面全体を数えるのに使わない。**
- **`allVisible = 2` は見えているレイヤの図形を渡す**（mac）。アクティブが `LO-A` のときはデザイン
  レイヤ 3 枚の 3012 件（レイヤオプションは「ほかをグレイ表示/スナップ」）、アクティブが
  シートレイヤ `LO-S` のときはその 2 件。**表示の設定で変わるので、数えるのに使わない。**
- **作った直後の図形は選択されている**（`IsSelected` が真。入れ子の中も）。
- **`NumSelectedObjects` はアクティブレイヤの分だけを数える**（mac）。別のレイヤにも選択された
  図形があるのに、`LO-S` のとき 2、`LO-A` のとき 11 を返した。

**画面の数との対応**:

| 画面 | 表示 | プローブの数 |
| --- | --- | --- |
| 情報パレット。`LO-A` で「すべてを選択」 | **11 図形** | `FirstMemberObj` → `NextObject` から `0` と `90` を除いた数・`allDrawing` の `LO-A` の数・`NumSelectedObjects` |
| 情報パレット。置き石が 2 つある `LO-A` で「すべてを選択」 | **11 図形** | 同上（列を素直に数えると 13 のノード＋終端） |
| 情報パレット。シートレイヤ `LO-S`（Windows・mac） | **2 図形** | `allSelected` の 2（ビューポートと、下記 7 の窓） |
| オーガナイザ「デザインレイヤ」の全列（窓を広げて右端まで見た） | **図形の数の列は無い** | `#`・縮尺・ストーリ・ストーリレベル・高さ・壁の高さ・GIS・タグ・切断面の高さ・カラー・不透明度・背景テクスチャ |

- 情報パレットは **SDK からアクティブレイヤを替えただけでは更新されない**ことがある（`LO-A` へ
  替えて選択が 11 件のときも「2 図形」のままで、「すべてを選択」で「11 図形」に変わった。mac）。

## 4. 消した図形・取り消した図形（mac）

**どちらも型 `90` の置き石になる。** `ForEachObjectN` は置き石を渡さないので、数は画面と合う。
`FirstMemberObj` → `NextObject` では置き石が見えるので、型で除けば画面と合う。

| 操作（`LO-A`） | 列（終端を除く） | うち型 `90` | `allDrawing` の `LO-A` |
| --- | --- | --- | --- |
| 見本を作った直後 | 11 | 0 | 11 |
| 最前へ | 12 | 1 | 11 |
| 最後へ | 13 | 2 | 11 |
| `LO-直線` を消去 | 13 | **3**（直線が同じ位置で置き石に替わる） | **10** |
| その消去を取り消し | 13 | 2（直線が同じ位置に戻る） | 11 |
| `LO-文字` を複製 | 14 | 2（末尾に `LO-文字-2`） | 12 |
| その複製を取り消し | 14 | **3**（`LO-文字-2` が同じ位置で置き石に替わる） | **11** |
| 続けて保存（ブリッジの別名保存。もう 1 周でも同じ） | 13 | **2**（複製を取り消した置き石だけ消える） | 11 |
| `LO-直線` を消去して「ファイル > 保存」 | 13 | **3**（**消去の置き石は保存しても残る**） | 10 |

- **図形が別の型のまま残るのではない。** #242 で「取り消した図形は保存するまで一覧に残る」と
  見えていたものの正体はこの置き石である（[Documents](Documents.md)）。保存で減るのは取り消した
  作成の分だけで、**並べ替えと消去の置き石は保存しても減らない**。
- **消した図形は名前でも引けない。** `GetNamedObject("LO-直線")` は消去の後は nil、取り消した後は
  戻った図形を返す。
- **消去を取り消して戻った図形は番地が変わる**（`0x7c0341b980` → `0x7bfa9b0140`）。**ハンドルを
  取り消しをまたいで持ち続けない。** 並べ替えでは番地は変わらなかった。
- ブリッジの別名保存を挟んでも、メニューの「取り消し」は 1 段で消去や複製を戻した。
  [Undo](Undo.md) の「別名保存は取り消しの段を 1 つ積み、1 段目では何も戻らない」（#223。
  `DoMenuName("Undo", 0)` で自分のイベントを戻した測定）と違う。どちらの条件が効くのかは
  ここでは切り分けていない。

## 5. 種別の名前

- **`GetObjectTypeN` の番号から名前を引く口は SDK に無い**【ヘッダ根拠】（`ISDK` にも VWFC にも
  無い。`TypeName` で引けるのは破線・レベル種別・部品の名前だけ）。**プラグインは自前の表を
  持つ。**
- 番号の一覧は `Objs.TDType.h`（`kLineNode = 2` 〜 `kWallStyleNode = 127`）。見本で出た番号:
  `2` 直線・`3` 矩形・`4` 楕円・`10` 文字・`11` グループ・`15` シンボル・`16` シンボル定義・
  `24` 押し出し・`68` 壁・`86` PIO・`122` ビューポート（ほかに子として `5` 多角形・`6` 円弧・
  `17` 点・`21` ポリライン・`84` CSG）。
- **PIO の名前は `VWParametricObj(h).GetParametricName()`**（`"Door"` / `"Window"`）。

## 6. 名前・クラス・外形

- **名前の無い図形の `GetObjectName` は空文字列。**
- **`GetObjectClass` → `ClassIDToName` でクラスの名前が引ける**（`"一般"`・`"LO-クラス"`。
  PIO の子には `"非出力"` もある）。置き石（型 90）は空。
- **複製すると名前に連番が付く**（`LO-文字` → `LO-文字-2`）。
- **`GetObjectBounds` はレイヤの縮尺を掛けない世界座標の mm。** 1:1 の `LO-A` と 1:50 の
  `LO-B` に同じ座標で作った矩形は、同じ `[0,100 → 1000,600]` を返した。
- **回した図形は外接矩形**（30° 回した 1000×500 は `[1250,100 → 2366.025,1033.013]`）。
- **文字は紙の上の大きさ×縮尺**（mac。同じ文字列・既定の書体）:

  | 文字 | 幅 × 高さ（mm） |
  | --- | --- |
  | `LO-A`（1:1）へ、1:1 のシートレイヤで作って移した | 21.251 × 6.350（Windows は 21.251 × 4.233） |
  | `LO-B`（1:50）をアクティブにして作った | **1062.567 × 317.500**（ちょうど 50 倍） |
  | 1:1 のシートレイヤで作って `LO-B` へ `AddObjectToContainer` で移した | **21.251 × 6.350**（**1:50 のレイヤにあるのに 1:1 のまま**） |

  - 移した文字が描き直しで大きさを変えるかは測っていない（`ResetObject` も掛けていない）。
- **3D の図形は平面の外接矩形**を返す（押し出しは底面の矩形）。高さは `GetObjectCube` の Z で
  読める（押し出し `0 → 1000`・ドア `0 → 2093`）。
- シートレイヤのビューポートの外形は紙の上の mm（mac は `[-43.065 → 43.065]`、Windows は
  `[-34.9 → 34.9]` 前後）。

## 7. シートレイヤ

- **シートレイヤを辿ると、ビューポート（型 `122`、名前 `"Viewport-1"`）と終端だけ**が出た
  （下の窓を除く）。`allDrawing` はシートレイヤの図形も渡す。図面全体を数えるときにシートレイヤを
  含めるかは呼ぶ側の決め（型 `122` で見分けられる）。
- **`CreateCustomObject` は、新しい PIO をアクティブレイヤに置く。** アクティブがシートレイヤ
  のときに壁の上の位置で窓を作ると、窓はシートレイヤに置かれ、デザインレイヤの壁には
  入らなかった（Windows・mac）。**作ったあとに `AddObjectToContainer(窓, 壁)` を呼ぶと `true` が
  返るのに、窓の親が nil になった**（どこにも属さない PIO が残る。Windows）。壁へ入れる口としては
  使わない。

## 8. 刻みの中の所要

**ブリッジの要求は刻みの中で処理される**（mac は `CFRunLoopTimer`、Windows は `SetTimer`）。
だから下の表の「ブリッジの要求の中」も刻みの中である。「`SetTimer` の刻みの中」は、プローブの中で
回したメッセージループから受けた別の刻み。

`LO-多`（矩形 3000）を、名前・外形・クラスを読みながら `FirstMemberObj` → `NextObject` で辿った
所要:

| | 1 回目 | 2 回目 | 3 回目 |
| --- | --- | --- | --- |
| Windows。ブリッジの要求の中 | 5.4 ms | 6.4 ms | 5.7 ms |
| Windows。`SetTimer` の刻みの中 | 8.4 ms | 5.3 ms | 7.3 ms |
| Windows。`SetTimer` の刻みの中の `ForEachObjectN(allObjects)`（全図面 3016 件を数えるだけ） | 2.0 ms | 0.7 ms | 1.0 ms |
| mac。ブリッジの要求の中 | 0.68 ms | 0.50 ms | 0.49 ms |
| mac。ブリッジの要求の中の `ForEachObjectN(allObjects)`（全図面 3017 件。レイヤごとの集計つき） | 1.13 ms | — | — |

- **刻みの中から辿ってよい**（落ちない。Windows の VM でも 3000 件で 10 ms に届かない）。

## Windows の VM では描画のスレッドで落ち続けた

見本を作ったあとの画面の操作で、**VW が 7 回落ちた**（`0xc0000005`・番地 0 の実行）。
WER のダンプを読むと、**落ちたスレッドには `d3d10warp.dll`（Windows のソフトウェア描画）の
番地しか無く、VW 本体・プラグインのコードは無かった**。主スレッドは待ちの中。
[Viewports](Viewports.md)（#248）・[Plug-in Modules](Plug-in%20Modules.md) にある、
この VM の描画の側の落ちと同じ形である。

中身を変えて切り分けた（見本を作り、アクティブレイヤを `LO-S` から `LO-A` へ切り替える）:

| 作ったもの | 結果 |
| --- | --- |
| レイヤだけ（図形なし） | 落ちない |
| 矩形 3000（`LO-多`） | 落ちない |
| シンボルだけ | 落ちた |
| 2D ＋シンボル | 落ちた |
| シンボル抜きの全部（2D・ドア・壁・押し出し・ビューポートなど） | 落ちた |
| **人がメニューで作ったシンボル**（プローブの図形なし・レイヤ切り替えもなし。「シンボル登録」の直後） | **落ちた** |

- **プローブ（SDK で作った図形）が原因ではない**——人がメニューで作っても落ちた。何が引き金か
  までは絞れなかった。同じ時刻に Windows のサービス（`webthreatdefsvc`）も落ちていて、
  VM そのものが不安定だった見込み【推定】。
- **mac では、同じ見本でアクティブレイヤの切り替え・選択・並べ替え・消去・複製・取り消し・保存の
  どれでも落ちなかった。**
- **Windows の 1〜3・5〜8 の値は、落ちる前にプローブが成功で返したログ**であり、落ちとは
  関係しない。
