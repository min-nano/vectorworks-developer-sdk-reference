# 進捗・診断・例外

長い処理の進捗表示・診断ログ・例外境界に関する SDK の実測。

## 進捗表示

- **進捗はダイアログ（`VWFC::Tools::CProgressDlg`）で出す。** ISDK に `vs.Message`
  （ステータスバー）相当は無い。
- **1 件ごとに `DoYield`** すると進み具合が見えるだけでなく、VW の再描画とイベント処理が
  戻り、キャンセルも効く（オーバーヘッドは実機で体感問題なし＝間引きは不要）。
- **進捗バーの重みは実測で按分する。** 1 件あたりの重さはオブジェクト種別で **3 桁**違い
  うる（実測例: シンボル 0.1ms/件に対し、スラブ 670ms/件・断面ビューポート 520ms/枚・
  平面ビューポート 480ms/枚・構造材 130ms/本）。件数比で配分すると、軽い要素がバーの
  大半を一瞬で進め、重い要素が数 % しか進まない**嘘の進捗**になる。

## 診断ログ

- **診断ログは 1 行書くたびにフラッシュする。** 無言クラッシュでも「ログ最終行の直後」が
  原因箇所になる。行頭に経過ミリ秒を付けると、どのフェーズで時間を使ったかも読める。
  出力先は一時ディレクトリにする（利用者の図面やデータの隣には置かない）。
- **ログはファイルと同時にメモリにも溜める**と、一時ディレクトリへ書けない環境でも
  ダイアログのログ欄に出せるし、表示のために読み直さずに済む。
- **実機の出力にはビルドの素性を添える。** 実機確認を往復する開発では「その出力がどの
  ビルドのものか」が分からないと切り分けが崩れる（[Investigation
  Techniques](Investigation%20Techniques.md)）。ログの見出しにビルド（名前・チャンネル・
  コミット・ブランチ）・実行環境・日時・対象ファイルを置く。
- **VW 本体のバージョンは C++ SDK から取れない。** `vs.GetVersionEx` は VectorScript に
  しか無く、SDK ヘッダ（`ISDK` ほか）に相当する取得 API は見当たらなかった（`sdk-grep`
  で全ヘッダを走査済み）。

## 例外境界

- **SDK コールバックへ例外を漏らさない。** メニューコマンドの本体（`DoInterface`）は
  処理全体を `try` で包み、`std::exception` と `catch(...)` の両方をエラーダイアログ
  1 通にする。**`plugin_module_main` の起動時処理も包む**——起動経路の未捕捉例外は
  VectorWorks の起動そのものを落とす。
