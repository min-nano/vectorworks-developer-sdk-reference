# 図面（ドキュメント）を開く・作る

プラグインの実行中に**別の図面（文書）を開いて、以後の描画をそちらへ向けられるか**の
調査（[issue #34](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/34)）。
背景は [issue #23](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/23) /
[#27](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/27) /
[#31](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/31)（[Undo](Undo.md)）
の続き。後半は CLI プラグイン（[vectorworks-plugin-command-line-interface](https://github.com/min-nano/vectorworks-plugin-command-line-interface)）
の `save` / `close` / `quit` のための、指定した図面の保存・閉じる・上書き保存の調査
（#240・#243・#283・#288・#290・#291・#293・#294・#298・#299・#304・#305）。
測った環境・プローブ・実測の表・ダイアログの文言・落ちた記録は
[計測記録](../Metrics/Documents.md)。

## まとめ

- **テンプレートから新しい図面を開くのは `OpenDocumentPath(<.sta>, false)`。** 無題の新規文書が
  テンプレートの中身を持って開き、カレント文書も描画先も即座に移る。
- **成否を戻り値で判定しない。** `CloseDocument()` も `SetObjectName()` も成功しながら `false`、
  `DoMenuName("Close", 0)` はいつも 0、`SaveActiveDocumentPath` は失敗の警告を出しても
  `GSError=0` のことがある。**`GetOpenFilesList` の件数・前面の `fileRef`・読み戻した値・
  ファイルの更新時刻**で確かめる。
- **`CloseDocument()` は確認を出さずに捨てる**（mac / Windows）。「閉じる」（`DoMenuName("Close", 0)`）は
  確認を出しうる。**「未保存の変更があるか」は SDK から読めない**（読めるのは「ディスクにあるか」だけ）。
- **既にあるファイルへの別名保存はできない**（ダイアログなしの 50331649、開いている図面と文字列が
  完全一致なら警告で止まる）。**上書き保存でダイアログが出る場面は、呼ぶ前に OS に聞けば当てられる**
  （mac と Windows で聞き方が違う。下記 #293・#298・#304）。

## 存在する API【ヘッダ根拠】

ISDK（`Interfaces/VectorWorks/ISDK.h`）に、複数の図面（文書）を開いて切り替えるための
一群の呼び出しがある。**すべて宣言と、実装ソース側の薄い転送コード（`gCBP` 経由で
Vectorworks 本体へ渡すだけ）までしか確認できていない**——実際に何が起きるかは
Vectorworks 本体側（SDK に同梱されていない）の実装に依存する。

| API | 効果（ヘッダのコメントより） |
| --- | --- |
| `bool OpenDocumentPath(IFileIdentifier* pFileID, bool bShowErrorMessages)` | `pFileID` の指すパスの文書を開く。`GS_OpenDocumentPath` の説明: 「Opens the document specified by inPath. Set inShowErrorMessages to false if you want to make sure no dialogs come up.」 |
| `bool CloseDocument()` | 現在の文書を閉じる。引数は無く、**保存の要否を指定する口が無い**（後述） |
| `bool GetActiveDocument(IFileIdentifier** ppOutFileID, bool& outSaved)` | 現在アクティブな文書のパスと、**ディスクに保存されたことがあるか**を返す（**未保存の変更があるかではない**。下記「[未保存の変更ありは読めない](#未保存の変更ありは読めない)」） |
| `void GetOpenFilesList(TVWArray_OpenFileInformation& outInformation)` | 現在開いている**すべての**文書の一覧を返す（後述） |
| `bool SwitchToOpenFile(Sint32 fileRef)` | 開いている別の文書へアクティブを切り替える。`fileRef` は `GetOpenFilesList` から取る |
| `GSError SaveActiveDocumentPath(IFileIdentifier* pFileID)` | アクティブな文書を、ダイアログを出さずに指定パスへ保存する（エラー時のアラートを除く） |

`GetOpenFilesList` が返す `SOpenFileInformation`（`ISDK.h`）は 1 文書につき

```cpp
struct SOpenFileInformation
{
    IFileIdentifierPtr  fpFileID;
    Sint32              fFileRef;         // SwitchToOpenFile へ渡す鍵
    bool                fIsActive;        // これがカレント文書か
    bool                fIsInMemoryOnly;  // true = まだディスクに保存されていない
};
```

を持つ。**Vectorworks は元から複数の文書を同時に開いた状態を扱える**（`sdk-grep` で
見つかった `VWResourceListCategorized.cpp` のコメント: "List resources from open
documents other than the current document"）。「今の文書を閉じてから次を開く」以外に、
「開いたまま裏に残し、`SwitchToOpenFile` で行き来する」という選択肢も API 上は存在する。

## テンプレート（`.sta`）から新規文書は作れる——**専用 API ではなく `OpenDocumentPath` で**

- **できる。** 「テンプレートから新規作成する」という名前の API は無く（ISDK / VWFC を検索して 0 件。
  [検索の表](../Metrics/Documents.md#テンプレートstaから新規文書は作れる専用-api-ではなく-opendocumentpath-で)）、
  **`.sta` のパスを `OpenDocumentPath` へ渡す**と、それを元にした無題の新規文書が開く（下記）。
- **【訂正】** 「メニューコマンドを名前で起動する汎用 API 自体が無い」というかつての根拠は誤りで、
  `ISDK::DoMenuName(name, chunkIndex)` が実在する（[Plug-in Interop](Plug-in%20Interop.md) の 2。
  [issue #217](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/217)）。
  ただし引数を渡す口が無く「このテンプレートから」を指定できないので、`OpenDocumentPath` のほうが扱いやすい
  （「新規」の内部名は未調査）。
- **空の新規文書は `OpenDocumentPath(nullptr, false)`**（公式の
  [`Info/Writing automated tests.md`](../Info/Writing%20automated%20tests.md) の用例。テンプレートは選べない）。
  **プラグインのメニューコマンド実行中（`DoInterface` の中）から呼んでも動く。**

## 既存ファイル（`.vwx` / `.sta`）をパス指定で開ける（実機確認済み）

- `OpenDocumentPath(IFileIdentifier*, bool)` に実在するファイルの `IFileIdentifier` を渡せば開ける
  （SDK の `VWFC/Tools/CatchSystemTest.cpp` の `TEST_OpenDocument` と同じ形。
  [コード](../Metrics/Documents.md#既存ファイルvwx--staをパス指定で開ける実機確認済み)）。
  `.sta` はテンプレートとして扱われる（下記）。

## 実機で確かめたこと（VW 2026 / macOS）

プラグインのメニューコマンドの中から実機確認プラグインで走らせた実測（一度も落ちていない。
[計測記録](../Metrics/Documents.md#実機で確かめたことvw-2026--macos)）。
**この節でいちばん値の張る教訓は「戻り値を信じない」こと。**

### コマンド実行中に呼んでよい

- **`OpenDocumentPath(nullptr, false)` はコマンド実行中に呼んで `true`。** `SwitchToOpenFile` /
  `CloseDocument` も呼べる。「[`CloseAllFilesAndQuitVectorworks`](#closeallfilesandquitvectorworks終了)」の
  **プラグイン読み込み中には呼べない**のような制約は、コマンド実行中については無い。

### カレント文書とカレントレイヤは即座に新しい文書へ移る

- **呼んだ瞬間に描画先が新しい文書へ移る**（`GetCurrentLayer()` も `GetActiveDocument()` も新しい文書を指し、
  `CreateRectangle` は新しい文書に入る。[実測](../Metrics/Documents.md#カレント文書とカレントレイヤは即座に新しい文書へ移る)）。
- **未保存の文書でも `GetActiveDocument` はパスを返す**（「アプリケーションのフォルダ＋無題の文書名」）。
  **保存済みかはパスの有無ではなく `outSaved` で見る。**
- **無題の連番は VW のセッション全体で進む**（新規が「名称未設定 3」になった）。**名前から文書を同定しない。**
- **図面が 1 枚も無ければ `GetCurrentLayer()` は `nullptr`**（落ちない）。閉じた文書のレイヤと後で開いた
  文書のレイヤが同じアドレスで返ったので、**ハンドルの値で文書を同定しない**
  （[Timers and Notifications](Timers%20and%20Notifications.md) の 4 の 8。mac / Windows）。

### `GetOpenFilesList` と `fileRef`

- **`fileRef` は連番ではない**（2 の次が 9）。**不透明な鍵**として `GetOpenFilesList` から取り、そのまま
  `SwitchToOpenFile` へ渡す。一度も保存していない文書は `fIsInMemoryOnly=yes`
  （[ダンプ](../Metrics/Documents.md#getopenfileslist-と-fileref)）。

### 前の文書のハンドルは、別の文書がアクティブでも読める

- 別の文書がアクティブでも、前の文書のレイヤハンドルへの `GetObjectName` は同じ値を返し、
  **`SetObjectName` で書くこともできた**（落ちない）。
- **ただし `SetObjectName` は `false` を返した。** 成否は読み戻して確かめる。
- 確かめたのは名前の書き換えだけ。**描くときは `SwitchToOpenFile` でその文書をアクティブにしてから**
  （[実測](../Metrics/Documents.md#前の文書のハンドルは別の文書がアクティブでも読める)）。

### 文書を開く・切り替える操作は undo イベントを開かない。**開いているイベントも壊さない**

- 開く・`SwitchToOpenFile` の前後で `IsCurrentlyBuildingAnUndoEvent()` は `no`（自分で開いていなければ）。
- **`IsCurrentlyBuildingAnUndoEvent()` は文書ごとの状態。** 文書 A でイベントを開いたまま B を開くと B では
  `no`、A へ戻ると `yes` で、中で作ったレイヤも残る
  （[表](../Metrics/Documents.md#文書を開く切り替える操作は-undo-イベントを開かない開いているイベントも壊さない)）。
- [Undo](Undo.md)「間接経路: スクリプトエンジン経由…」でイベントを終わらせていたのは取り消しの実行で、
  文書を開く操作ではない（切り分け済み）。
- **イベントは開いた文書の中で閉じる**のが素直（記録がどちらの文書に積まれるかが曖昧になるため）。

### `SwitchToOpenFile` で行き来できる

- `SwitchToOpenFile(<開く前の fileRef>)` は `true` で、**カレントレイヤも開く前と同じハンドル**に戻る。
  **開いたまま裏に残して行き来する**が動く。

### `CloseDocument()` は **`false` を返しながら閉じている**——未保存の変更も黙って捨てる

- **戻り値は当てにならない**（mac で 5 回とも `false` で 5 回とも閉じた）。**判定は `GetOpenFilesList` の件数でする。**
  （この節は一度「閉じられない」と書いて訂正した。[実測](../Metrics/Documents.md#closedocument-は-false-を返しながら閉じている未保存の変更も黙って捨てる)）
- **保存確認ダイアログは出ない**（73〜237 ms で戻る）。**未保存の変更は黙って捨てられ、人の作りかけを
  消しうる。** 自分が開いた文書だけを閉じるなどの判断は呼び出し側の責任
  （`outSaved` は未保存の変更を表さないので使えない。下記「未保存の変更ありは読めない」）。
- 「保存してから閉じる」も通る（`SaveActiveDocumentPath` が `GSError=0`）が、捨ててよい文書を保存する必要は無い。

#### Windows と、「閉じる」で確認が出る図面（#305。mac も）

[issue #305](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/305)。
[表（Windows・mac）](../Metrics/Documents.md#windows-と閉じるで確認が出る図面305mac-も)。

- **Windows でも mac と同じ。** 戻り値は Windows 17 回・mac の全回とも `false` で、全部閉じた。
  **確認は 1 度も出ない**——「閉じる」なら確認が出る図面（無題・無変更、`OpenDocumentPath` で開いただけ、
  読み取り専用・使用中・古い版を開いたコピー、大きな図面）でも出ない。未保存の変更は黙って捨てる。
- **大きな図面（11.2 万件）は描画の後だけ長い**: 描画の前は Windows の VM で 0.5〜0.6 秒・mac 0.15 秒、
  描画の後は Windows の VM 8.9 秒・mac 2.9 秒。Windows では**約 5 秒を超えるので応答なしの表示になりうる**（#290）。
  #290 の「閉じる」で確認が出るまでの 31.8 秒は、確認を出す前の描画だったと読める【推定】。
- **閉じた後に前へ出るのは最後に開いた図面**（mac / Windows）。覚えておいた `fileRef` へ `SwitchToOpenFile`
  すれば `true` で、カレントレイヤも同じハンドルに戻る。
- **`.<名前>.lck` は閉じると消える。** コピーは元のフォルダに `.lck` を作らず、閉じた後にアプリのフォルダにも
  ファイルは残らない。

### `.sta` を渡すとテンプレートとして扱われる——**無題の新規文書が開く**

**この節が issue #34 の本題への答えである。**

- **`.sta` のパスを `OpenDocumentPath` へ渡すと、そのファイル自体ではなく、それを元にした無題の新規文書が
  開く**（`saved=no`。Finder で `.sta` をダブルクリックしたときと同じ扱い。
  [ログ](../Metrics/Documents.md#sta-を渡すとテンプレートとして扱われる無題の新規文書が開く)）。
- **中身も引き継がれる**（`.sta` の中のレイヤが、開いた無題文書のカレントレイヤだった）。
  「テンプレート由来の初期状態は再現できない」という以前の結論は**誤り**だった。
- **`.vwx` を渡したときは無題にならない**（パスは渡したパス、`saved=yes`）。**扱いを分けているのは拡張子**と
  読める【推定】——中身の形式まで見ているかは確かめていない。

### 既に開いているファイルは、もう一度は開けない

- 開いている文書のファイルを `OpenDocumentPath` へ渡すと **`false`**（20 ms。即座の拒否で、ダイアログではない）。
  閉じてから渡せば `true`。
- **引っ掛かりやすい**: `SaveActiveDocumentPath` で保存するとその文書自身が保存先のファイルになるので、
  **「保存 → そのパスを開く」は必ず失敗する**（[実測](../Metrics/Documents.md#既に開いているファイルはもう一度は開けない)）。
- 同じファイルを**別の文字列**で開くと、拒否ではなくコピーで開く（下記 #294・#299）。

## 未保存の変更ありは読めない

**問い**（[issue #240](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/240)）:
保存済みの図面を変更した状態（未保存の変更あり）を SDK から取れるか（CLI の `quit` の事前確認のため）。

**答え: 取れない。** 読める手掛かりは `GetActiveDocument` の `outSaved` と `GetOpenFilesList` の
`fIsInMemoryOnly` の 2 つだけで、**どちらも「ディスクに保存されたことがあるか」を表す**。
macOS の窓の「編集済み」（`NSWindow` の `isDocumentEdited`）も、保存の確認とは食い違う。

### 読む口は 2 つしか無く、どちらも「ディスクにあるか」【ヘッダ根拠】

- **SDK に「変更あり」を読む宣言は無い。** `SDK Index/` を `Modified` / `Dirty` / `Changed` /
  `Saved` で引いて、文書の状態として見つかるのは**変更ありに「する」側**の
  `ISDK::MarkCurrentDocChanged()`（`ISDK.h:1386`。`kcbMarkCurrentDocChanged`）と、
  メニューの有効条件 `EMenuEnableFlags::DocChanged`（`MiniCadCallBacks.h:4950`）だけ。
  `IApplication::GetActiveDocument(IDocument**)` で取れる `IDocument` は設定ダイアログを
  出す 4 つの関数しか持たない（`IDocument.h:16-19`）。
- `outSaved` の意味は旧 API の説明文に書いてある（`APIBase.Legacy.Defs.h`、
  `GS_GetActiveDocumentN`）: 「The saved parameter indicates whether the document has been
  **saved to disk**. If it has not, then activeDocumentPath is only a file name.」
  ——**ディスクにあるか**であって、変更の有無ではない。

### 実測: 正解（「閉じる」で保存の確認が出るか）と突き合わせた

mac（VW 2026・arm64）で、1 回の実行で 1 段だけ進め、正解を「閉じる」の保存の確認で機械的に取った
（[測り方と表](../Metrics/Documents.md#実測-正解閉じるで保存の確認が出るかと突き合わせた)）。

- **全ケース・全段で `outSaved == !fIsInMemoryOnly`。** 保存済みの 5 ケースはどれも `outSaved=yes` で、
  **確認が出るケースと出ないケースを見分けられない**。**値が変わるのは保存した瞬間だけ。**
- **窓の「編集済み」も正解ではない。** 取り消した後と `MarkCurrentDocChanged()` の後は `no` なのに確認が出る
  （undo の段の位置を追っているだけと読める【推定】）。無題の図面は開いた瞬間から `yes`。
- **VW の「変更あり」は取り消しでは消えない。消えるのは保存したときだけ。**
- **「変更あり」になるのは undo イベント付きの変更と `MarkCurrentDocChanged()`。** **undo イベントの外の
  書き込みは「変更あり」にしない**（刻みの中で。[Timers and Notifications](Timers%20and%20Notifications.md)
  の 4 の 9 の【推定】をここで確かめた）。**閉じれば黙って捨てられる。**
- **無題の図面は、何もしていなくても確認が出る**（「閉じる」で）。
  - #230 で「新規の図面に刻みの中で線を引いただけでは終了の確認が出なかった」のは、その図面がブリッジに
    よって既に一時ファイルへ保存されていた（＝「保存済み・undo の外の変更」と同じ形）ためと読める【推定】。
- **取り消された図形は、保存するまで一覧に残る**（`FirstMemberObj` / `NextObject` で数えた数が減らない）。
  **図形数で「取り消しが効いたか」を判定しない。** 残っているのは図形ではなく型 `90` の置き石で、
  `ForEachObjectN` には出ない（[Layer Objects](Layer%20Objects.md) の 4。#282）。
- **刻みの中から呼んでよい**（`GetActiveDocument` は 1 回 7〜94 µs。#241）。**図面 0 枚・起動直後の刻みでも
  `GetOpenFilesList()` は落ちない**（[Timers and Notifications](Timers%20and%20Notifications.md) の 4 の 1・4 の 8）。
- **同じパスへの上書き保存は通る**（`GSError=0`・パスも変わらない。#241・#242）。殻のブリッジの「既にある
  ファイルへの**別名**保存は通らなかった」（`plugin/src/McpBridge.cpp`）とは別の場面。
- 正解は「閉じる」の確認で取った。**終了（`CloseAllFilesAndQuitVectorworks(true)`）の確認も同じ判定**と
  見ている【推定】（#230 の終了の実測と 3 ケースが一致）。
- **Windows では測っていない。** `outSaved` の意味は SDK の説明文どおりなので変わらないと見る【推定】。
  窓の「編集済み」は macOS だけの口。

### `quit` の事前確認への帰結

- **ダイアログなしで分かるのは「無題の図面がある」までである。** `GetOpenFilesList` の
  `fIsInMemoryOnly=yes`（無題）を拾えば、その図面は**変更が無くても**保存の確認を出す
  （「閉じる」で実測。終了でも同じと見る【推定】）。**保存済みの図面に未保存の変更が
  あるかは、事前に知る口が無い。**
- **未保存の変更が無いときの `CloseAllFilesAndQuitVectorworks(true, false)` は、確認なしで
  終わる。** 確認があるときは**キャンセルされても呼び出しから戻り、図面は残る**（件数で
  分かる）。どちらも #230 で実測済み（下記「[呼んだ後の振る舞い](#呼んだ後の振る舞いmac--windows-で実測)」）。
  **issue #240 の 5・6 はこれで答えが出ている**——確認は呼び出しの時点の状態で決まるので、
  「確かめてから呼ぶまでの間に変更ができた」場合も、ふつうに確認が出て、キャンセルなら戻る。
- したがって「確認を出さない」を保証する手は、事前確認ではなく次のどれかになる:
  1. **保存してから終える**——開いている保存済みの図面を順に `SwitchToOpenFile` →
     `SaveActiveDocumentPath(<その図面自身のパス>)` で上書き保存すれば、変更の有無に
     関わらず確認の種は消える（上書き保存が通ること、保存で「変更あり」が消えることは
     上記のとおり実測）。**人の変更を黙ってディスクへ書く**ので、明示の指定（`--save`
     など）を要する設計になる。無題の図面には保存先が無いので、この手では消せない。
  2. **捨てて終える**——`CloseAllFilesAndQuitVectorworks(false, …)`（確認なしで閉じる）。
     **人の変更を黙って捨てる**ので、同じく明示の指定（`--force` など）でだけ使う。
  3. **確認を出す前提で呼ぶ**——ダイアログが出うることを受け入れ、キャンセルされたら
     （戻った後も図面が残っていたら）エラーで応える。
  事前確認で拾えるのは無題の図面だけなので、それを「未保存の一覧」として返すなら
  **「保存済みの図面の変更は含まれない」**ことを利用者に言わなければならない。
- **自分で数えて持つ【推定・未検証】。** `kNotifyDocPostSaved` / `kNotifyDocOpen` で「保存
  時点」を記録し、`kNotifyUndoEndEvent` で「変更あり」を立てる作りは考えられる。突き合わせの
  表（[計測記録](../Metrics/Documents.md#実測-正解閉じるで保存の確認が出るかと突き合わせた)）で
  VW の「変更あり」が立ったのは **undo イベント付きの変更**と **`MarkCurrentDocChanged()`** で、
  **取り消しでは消えない**ので、「保存以降に undo イベントが 1 つでも閉じたか」はその表と合う。
  ただし **`MarkCurrentDocChanged()` は通知なしに変更ありにする**ので（他のプラグインが
  呼べば見えない）、**正確な代わりにはならない**。

## 指定した図面を保存する・閉じる（前面に依存せず）

**問い**（[issue #243](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/243)）:
CLI の `save` / `close` は**引数（パス）で指定した図面**を扱う。新しいパスへ保存できるか、前面を元に
戻せるか、「閉じる」で保存の確認がいつ出るか。mac で OS タイマーの刻みの中から測った
（[環境とプローブ](../Metrics/Documents.md#指定した図面を保存する閉じる前面に依存せず)）。

### 手順——`GetOpenFilesList` で引き、`SwitchToOpenFile` で前へ出し、前面を戻す

```cpp
// 1. 前面を覚える（fileRef とカレントレイヤ）
// 2. GetOpenFilesList から、パスが一致する項目の fFileRef を引く
gSDK->SwitchToOpenFile(targetRef);
gSDK->SaveActiveDocumentPath(fileID);   // 保存（新しいパス / 自分のパス）
gSDK->DoMenuName("Close", 0);           // 閉じる（確認が出うる。下記）
// 3. 閉じた後の前面は「元の前面」とは限らない → 覚えた fileRef へ戻す
gSDK->SwitchToOpenFile(originRef);
```

- **前面は戻せる。** 元の図面へ `SwitchToOpenFile` で戻すと、`fileRef` も**カレントレイヤのハンドルも**元どおり
  （裏の図面を閉じた後でも）。
- **閉じた後に前へ出るのは、元の前面ではない**（いちばん最近開いた図面）。元へ戻すのは呼ぶ側の仕事。
- **図面は「パス」で一意に決まる**（同じファイル名の別フォルダの 2 枚も見分けられる）。**無題の図面のパスは
  「アプリケーションのフォルダ＋名称未設定 N」で、ファイルとしては存在しない**ので、無題の図面を指すなら
  `fileRef` のほうが確か。

### `SaveActiveDocumentPath`——新しいパスへは通る。既存のファイルへは通らない

[表](../Metrics/Documents.md#saveactivedocumentpath新しいパスへは通る既存のファイルへは通らない)（mac）。

- **まだ無いパスへは通る**（`GSError=0`・ダイアログなし。無題からも、保存済みの別名保存も）。
  **別名保存は「名前を付けて保存」と同じく、図面ごと保存先へ移る。** 元のファイルは保存した時点の中身のまま残り、
  別の図面として開き直せる。自分のパスへの上書き保存も通る。
- **既存のファイルを上書きする別名保存はできない。** 開いていないファイルなら**ダイアログなしで
  `50331649`（`0x03000001`）**を返し、ファイルには触れない。**別の図面が開いているファイルだと警告
  「このファイルはすでに開かれています。」が出て、人が OK を押すまで戻らない**（SDK の説明文の
  「エラー時のアラート」がこれ）。**呼ぶ前に `GetOpenFilesList` のパスと突き合わせて断る。**
  上書きしたいなら呼ぶ前にファイルを消すしかない【推定：消してから保存は試していない】。
- 殻のブリッジの「既にあるファイルへの別名保存は通らなかった」（`plugin/src/McpBridge.cpp`）はこの 50331649 の場面。
- 保存先が一時フォルダ（`$TMPDIR` の下）でも通る。
- 親のフォルダはあるが書き込めない場面は「[新しいパスへの保存で、親のフォルダに書き込めないとき（#304）](#新しいパスへの保存で親のフォルダに書き込めないとき304)」。
  **ファイルを足せなければダイアログなしで断られるが、`VW Backup` を作れないだけなら保存は通ってダイアログが出る**（Windows・mac）。

### 「閉じる」（`DoMenuName("Close", 0)`）——**保存した直後なら確認なしに閉じる**。確認の有無は「保存済みか」では決まらない

[表と切り分け](../Metrics/Documents.md#閉じるdomenunameclose-0保存した直後なら確認なしに閉じる確認の有無は保存済みかでは決まらない)（mac）。

- **戻り値はどの回も 0**（閉じても、キャンセルしても）。**成否は件数と対象の `fileRef` が残っているかで見る。**
- **刻みの中から呼べる。** 確認が出たら**人が押すまで戻らない**。**キャンセルされても呼び出しは戻り、図面は残る。**
- **確認が出ない**: 新しいパスへ保存した直後・開き直して上書き保存した直後・人が「開く」で開いて何もしていない図面。
- **確認が出る**: 無題・無変更、そして **`OpenDocumentPath` で開いた保存済みの図面（何もしなくても）**。
  原因は開き方で（人が開いた図面は出ず、`OpenDocumentPath` で開いた図面は人の ⌘W でも出る）、
  **`OpenDocumentPath` で開くと開いた時点で「変更あり」になっている**。何が変更扱いかは分からない【推定：
  開くときの変換や更新】。開いた後に同じパスへ上書き保存してから閉じれば出ない。
- **undo イベントの外で足した図形は「変更あり」にしない——そして「閉じる」で黙って消える**（制御を返した後でも）。
  [「未保存の変更ありは読めない」](#未保存の変更ありは読めない)（#242）と同じ。**「確認が出ないから変更は無い」とは
  読めない**ので、図面に書く道具を持つプラグインは、閉じる前に**呼ぶ側が保存する**か、undo イベント付きで
  書く（または `MarkCurrentDocChanged()` で変更ありにする）。後者なら人の「閉じる」でも確認が出る。

### CLI の `save` / `close` への帰結

- **`save <パス> --to <新しいパス>`（無題の図面の保存・別名保存）は成り立つ。** 保存先が既に
  あるなら、呼ぶ前に断る（開いているファイルなら警告のダイアログが出てしまうため）。
- **`close` は「保存した直後」でないと確認が出うる**——無題・`OpenDocumentPath` で開いただけ・
  `MarkCurrentDocChanged()` の図面では出る。**人が開いて何もしていない図面なら出ない**。
  CLI に `open` を持たせる（`OpenDocumentPath` で開く）なら、**開いただけの図面でも `close` で
  確認が出る**ことを前提にする（`save` してから `close` すれば出ない）。逆に、**刻みの中で描いただけの変更は確認なしに捨てられる**。確認が出て
  キャンセルされたら、件数が減っていないことで知り、エラーで応える（`quit` と同じ。上記
  「`quit` の事前確認への帰結」）。
- **「保存してから閉じる」の 2 手なら、確認は出ない**（3 例。開き直した図面でも出なかった）。
  呼ぶ側に保存の責任を持たせる設計（#243 の背景）と合う。

### Windows——振る舞いは mac と同じ。違うのは**パスの比べ方**と、**開ける図面は 8 枚まで**

**問い**（[issue #283](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/283)）:
上の mac の結果が Windows でも成り立つか。殻の `SetTimer` の刻みの中から測った
（[環境](../Metrics/Documents.md#windows振る舞いは-mac-と同じ違うのはパスの比べ方と開ける図面は-8-枚まで)）。

#### パスの形——**渡した文字列がほぼそのまま残る**（区切りだけは `\` に揃う）

- **無題の図面は mac と同じく「アプリケーションのフォルダ＋`名称未設定 N`」**（`C:\Program Files\VW2026\名称未設定 N`。
  ファイルとしては存在しない。N はセッション全体の連番で、閉じても戻らない）。
- **保存済みの図面のパスは、`SaveActiveDocumentPath` に渡した文字列がそのまま `GetOpenFilesList` に出る。**
  直るのは区切りだけ（`/` → `\`）。**ドライブ文字の大小・名前の大小・8.3 の短い名前は直らない**
  ＝同じファイルが渡し方しだいで別の文字列になる（[例](../Metrics/Documents.md#パスの形渡した文字列がほぼそのまま残る区切りだけは--に揃う)）。

- **260 文字以上のパスへは保存できない**（50331649・ダイアログなし。`LongPathsEnabled=0`）。使えるのは
  259 文字まで【推定】（ちょうど 260 文字は測っていない）。

#### 保存先が既にある——**ダイアログが出るのは「開いている図面のパス」と文字列が一致するときだけ**

- **「すでに開かれています」の判定は、開いている図面のパスとの文字列の完全一致**（大小も区別）らしい【推定：
  実装は見ていない】。一致しなければ「ディスクにあるか」で**ダイアログなしで** 50331649
  （[表](../Metrics/Documents.md#保存先が既にあるダイアログが出るのは開いている図面のパスと文字列が一致するときだけ)）。
- **＝既にあるファイルへはどの形で渡しても保存できない。** ダイアログが出るかだけが文字列で変わる。
- **自分のパスへの上書き保存も、文字列が完全一致のときだけ通る**（大小だけ違うと「既にある」で断られる）。

#### 「閉じる」（`DoMenuName("Close", 0)`）——mac と同じ。**確認の最中は同じ `SetTimer` が入り直す**

- **内部名 `Close` は Windows でも引ける。** 戻り値はいつも 0。確認の出る・出ないも mac と同じ
  （無題・無変更と、`OpenDocumentPath` で開いただけの図面で出る）。キャンセルすれば戻り、図面は残る。
- **確認の窓のボタンの ID は標準と違う**: 「はい(&Y)」＝1・「キャンセル」＝6・「いいえ(&N)」＝7（`IDCANCEL`＝2 ではない）。
- **確認の最中、`Close` を呼んだ `SetTimer` の刻み自身が入り直す**（16〜19 回。確認ダイアログのメッセージループが

#### 前面を戻す

- mac と同じ。裏の図面を保存・閉じた後に `SwitchToOpenFile` で戻すと `fileRef` もカレントレイヤのハンドルも元どおり。
  **前面の図面を閉じると前へ出るのは別の図面**。

#### 開いていられる図面は 8 枚まで——9 枚目は**ダイアログで止まり、`OpenDocumentPath(nullptr)` は `true` を返す**

- 8 枚開いた状態で `OpenDocumentPath(<.vwx>, false)` は警告（OK だけ）で止まり、押すと `false`。
- **`OpenDocumentPath(nullptr, false)` は同じ警告を出したうえで `true` を返す**——図面は開いていない。
  **新規を開けたかは件数と前面の `fileRef` で確かめる**（プローブはこれで走り出しの図面を保存して閉じてしまった）。
- mac に同じ上限があるかは測っていない（[実測](../Metrics/Documents.md#開いていられる図面は-8-枚まで9-枚目はダイアログで止まりopendocumentpathnullptr-は-true-を返す)）。

#### CLI への帰結（Windows）

- **`save --to` の衝突は、開いている図面のパスと比べても防ぎ切れない。** 既にあるファイルへは
  どの形でも保存できないので、**呼ぶ前に「保存先がディスクにあるか」で断る**（ファイルシステムに
  聞くので大文字と小文字・8.3・`/` を気にしなくてよい）。開いている図面との比較（区切りを
  揃え、NFC、大文字と小文字を区別しない）は、それより先に「どの図面と衝突するか」を
  言うためだけのものになる。**比べ方が文字列の完全一致より緩い分には害が無い**（ダイアログが
  出るのは完全一致だけなので、緩く比べて断れば必ずダイアログの手前で止まる）。
- **`documents` が返すパスは正規化されていない**（`c:\`・8.3 がありうる）。利用者の渡した
  パスと突き合わせるときは、両方を長い名前（`GetLongPathNameW`）に直し、大文字と小文字を
  区別せずに比べる。**自分のパスへ上書き保存するときは、利用者の文字列ではなく
  `GetOpenFilesList` が返した文字列をそのまま `SaveActiveDocumentPath` に渡す**（大小が
  違うだけで断られる）。
- **刻みから `close` を呼ぶ道具は、確認の最中に同じタイマーが入り直すことを前提にする**
  （入れ子の要求を見送る旗。`quit` と同じ）。
- 新規を開く道具は、**開けたかを件数で確かめる**（8 枚の上限で `true` のまま開かない）。
- 260 文字以上の保存先は、呼ぶ前に断ってよい（通らない。境目は上の `MAX_PATH`）。

### 大きな図面でも、呼び出しの中で終わる（#290。mac。Windows は下の節。**実務の図面は測っていない**）

  置き換える**（置き換えの瞬間に 1 度だけパスにファイルが無い時点を見た）。**ロック `.<名前>.lck` は図面のパスに付いて動く。**

  【推定: メモリ不足】）。**大きな図面を作って試すときは、メモリを見張って VW を止める仕掛けを横で動かす。**

### CLI の `close` / `save` への帰結（#290）

- **戻った直後に `GetOpenFilesList` を読む作りのままでよい**（mac・Windows）。閉じつつある図面を「残っている」と
  誤読する場面も、書きかけのパスを返す場面も、測った範囲では無かった。
- **最中は何も応えない**（`busy` すら返せない）。mac では刻みが入り直さないので、受け付けの入れ子は
  起きない。**Windows で入れ子になるのはダイアログの間だけ**で、ふつうの保存・閉じるでは起きない。
- **呼ぶ側の 30 秒の上限は、測った範囲の保存・閉じるにはおおむね足りる。** Windows の VM で超えたのは、描画前の
  図面を閉じて確認が出た 1 回（34.6 秒）である。実務の図面では確かめていないので、長くかかる前提で作る。
  **上限を過ぎても処理は続く**ことを道具の説明に書く、という issue の方針はそのまま要る。
- **`close` / `save` より `open` の後を心配する。** 開いた後の描画で次の要求が長く待たされ、**その長さに
  上限は無い**。呼ぶ側のタイムアウトを「失敗」と読まない。Windows の描画前の図面では、その待ちが `close` の
  呼び出しの中へ移ることがある。
- **Windows は約 5 秒を超える `save` / `close` で応答なしの表示になる。** 図面は壊れていないので、失敗と読まない。

## 利用者の図面を上書き保存する——ダイアログが出る場面と、保存先の文字列（#288）

**問い**（[issue #288](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/288)）:
古い版・読み取り専用・ほかで開かれているファイルを、OS タイマーの刻みの中から自分のパスへ上書き保存すると
何が起きるか。保存先 `to` の形と、「すでに開かれています」の比べ方。取り消しの段は [Undo](Undo.md)。
この節の表は mac の実測で、Windows は下の「Windows——測れた範囲」
（[環境と見張りの作り](../Metrics/Documents.md#利用者の図面を上書き保存するダイアログが出る場面と保存先の文字列288)）。

**結論: 古い版・読み取り専用・使用中のファイルは「ファイルに結び付かないコピー」として開くので、そもそも
上書きにならない（開くときに確認が出るだけ）。見分ける印は `fIsInMemoryOnly=yes`。上書き保存の呼び出しで
ダイアログが出るのは、図面のファイルがディスクから消えたときと、開いた後で読み取り専用になったとき**である（mac）。

### 開いた図面の状態——古い版・読み取り専用・使用中は、どれも元のファイルに結び付かない

- **人が開く（`open -a`）と確認が出る**が、**`OpenDocumentPath` は確認を出さずにコピーへ落ち、戻り値は `true`**。
  開いた図面のパス（`/Applications/VW2026/v2024 v2026.vwx`・`ro コピー 1`・`held コピー 1`）が渡したパスと違うことでしか
  気付けない（[表と確認の文言](../Metrics/Documents.md#開いた図面の状態古い版読み取り専用使用中はどれも元のファイルに結び付かない)）。
- 図形は元のファイルのまま読め、元のファイルは不変。変換後の名前のファイルは元のフォルダにできない。

### 上書き保存——`fIsInMemoryOnly=yes` の図面の「自分のパス」は、アプリのフォルダである

[表と警告の文言](../Metrics/Documents.md#上書き保存fisinmemoryonlyyes-の図面の自分のパスはアプリのフォルダである)（mac）。

- コピー（古い版・読み取り専用・使用中）から元のファイルへの保存は 50331649・ダイアログなし。
- **`GetOpenFilesList` のパスをそのまま保存先に渡すと、無題の図面やコピーでもアプリのフォルダ（`/Applications/VW2026/`）へ
  黙って保存される**（拡張子も足されない）。「自分のパスへ」は `fIsInMemoryOnly=no` の図面に限る。
- **ダイアログが出るのは 2 場面**: ファイルをディスクから**移した / 消した**（警告「指定したファイルが見つかりません。…」・
  50331649・押すまで戻らない）と、**開いた後でファイルを読み取り専用にした**（警告「ファイルの保存に失敗しました。…」なのに
  **`GSError=0` でファイルは置き換わる**。2 回目の保存では**図面のパスがアプリのフォルダへ変わり `outSaved=no`**）。
- **上書き保存のダイアログを避けるには、呼ぶ前に自分のファイルがディスクにあること、書き込めることを見る。**
  書き込めないときの `GSError` は 0 なので、**戻り値では失敗も成功も分からない**。親のフォルダ・ロック・ACL は下の #293。
- ほかの利用者・ほかの計算機が開いている場面は試していない（確認の文言の括弧の中が変わるだけと読める【推定】）。
- 読み取り専用のフォルダの中の、書き込める図面の上書きは、警告が 2 枚出てファイルは変わらない（#293）。

### ロックファイル `.<名前>.lck`

- 図面を開いている間、ファイルの隣に隠しファイル `.<拡張子を除いた名前>.lck`（XML。`User` / `Computer` / `LockedTime`）が
  でき、閉じると消える（[中身](../Metrics/Documents.md#ロックファイル-lck)）。`LockedTime` は 1904 年起点の現地時刻の秒らしい【推定】。
- **ファイルがあるだけでは「使用中」にならない**（他人の名前の `.lck` を手で置いても確認なしに開き、自分の名前へ書き換えた。
  生きているかは別の手段で見ている【推定】）。**`.lck` を読んで「使用中」と断る判定は当てにならない。**
- SIGTERM で終了させても `.lck` は消えた。

### 保存先 `to` の形（無題の図面から）

[表](../Metrics/Documents.md#保存先-to-の形無題の図面から)（mac）。

- **拡張子は足されず、変換もされない**（`noext`・`.txt`・`.sta`・`.dwg` も、その名前で中身は Vectorworks の形式）。
- **親のフォルダが無い・親がファイル・親が書き込めない・既にある（大小違いも。APFS は区別しない）は、どれも
  ダイアログなしの 50331649。フォルダは作られない。** `/` で終わるパスは 50331652（`0x03000004`）。
- `bad?name.vwx` / `bad:name.vwx` / `trail.vwx.` はその名前のまま保存（Windows は化ける。下記）。
- **保存すると保存先の隣に `VW Backup/<名前>-バックアップ-<年月日時分秒>.<拡張子>` ができる**（この機械の環境設定で）。
- `.sta` で保存したファイルをテンプレートとして開けるかは試していない。
- **呼ぶ前に断るなら**: 拡張子は `.vwx` を求める。親のフォルダの有無はダイアログに関わらないので、断るのはエラーの文の
  ためだけ。

### 「このファイルはすでに開かれています。」の比べ方（mac）——**Windows と同じ文字列の完全一致**

[表](../Metrics/Documents.md#このファイルはすでに開かれていますの比べ方macwindows-と同じ文字列の完全一致)。

- **判定は文字列の完全一致**（ファイルシステムの同一性を見ない）。**ファイルを移した / 消した後でも同じ文字列なら出る**ので、
  開いている図面の一覧とだけ比べている【推定】。大小違い・NFD 違いは、ファイルがあれば 50331649（既にある）、
  ファイルを移した後なら `GSError=0` で保存され、**同じファイルを指す図面が 2 枚開いたまま**になる。
- **読み戻しの文字列は渡したまま**（NFD は NFD のまま）。**同じファイルでも入口で文字列が変わる**（`open -a` は
  `/private/var/folders/…`、`SaveActiveDocumentPath` に `/var/folders/…` を渡すとそのまま）。
- 自分のパスの文字列違い（大小・NFD・`/private` 付き）は 50331649・ダイアログなしで上書きにならない（Windows と同じ）。

### CLI の `save` への帰結（mac）

- **`to` を省いた `save` は `fIsInMemoryOnly=no` の図面に限る。** `yes`（無題・古い版・読み取り専用・
  使用中のコピー）は、呼ぶ前に「`to` が要る」と断る。そうしないとアプリのフォルダへ黙って書く。
- **呼ぶ前に、自分のファイルがディスクにあること、書き込めることを確かめて断る。** この 2 つが上書き保存で
  ダイアログが出る場面である。書き込めない場面を見逃すと 2 回目の保存で図面のパスがアプリのフォルダへ移る。
- **`to` と開いている図面の比較は「区切りを揃えて完全一致」で足りる。** 出るのは完全一致だけで、
  ディスクにあれば別に断る。ただし**緩く比べて断っても害は無く**、ファイルを移した後に同じファイルを
  指す 2 枚目ができるのを防げるので、**いまの予定（NFC・大文字と小文字を区別しない）のままでよい**。
- `to` には `.vwx` を求める。親のフォルダの有無も断ってよい（どちらでもダイアログは出ない）。
- **利用者が古い版のファイルを `open`（CLI）で開くと、確認なしにコピーになる。** 開いた後のパスを
  返して、元のファイルには保存されないことが分かるようにする。

### Windows——測れた範囲（#288）

3D アクセラレーションの無い VM・**管理者で昇格した VW**（普通の利用者の権限では測っていない）
（[環境・表・落ちた記録](../Metrics/Documents.md#windows測れた範囲288)）。

- **mac と同じだったもの**: 拡張子の扱い・大小違い・親が無い / ファイル / 書き込めない（50331649・ダイアログなし）・
  `\` で終わるパスと相対パス（50331652）・「すでに開かれています」・読み取り専用を開くとコピー・無題の図面を一覧のパスへ保存すると
  アプリのフォルダ（`C:\Program Files\VW2026\`）にできる（昇格しているため）・`.lck`。人が開く入口 `Vectorworks2026.exe <ファイル>` は動いている VW へ渡る。
- **Windows だけのもの**:
  - **VW は開いている間ずっとファイルを握る**（移す・消す・親のフォルダの改名ができない）。なので mac の「ファイルが消えた」場面は
    ふつうは起きない。**ドライブごと消える**（`subst` を外す）と警告「ディスクの空き容量がありません。」→ 50331649。
  - **`\` 以外の区切りと禁止文字は黙って名前に化ける**（`/` → `%5C`・`?` → `%3F`・`:` → `%3A`。`GSError=0` で、渡したパスにファイルはできない）。
    `trail.vwx.` は `trail.vwx` ができ、図面のパスは点付きのまま。
  - **NFD は別のファイルになる**（NTFS は区別する。一覧に見た目が同じ 2 行）。
  - **開いた後で読み取り専用にしたファイルは、断られずに置き換わる**（元は `<名前>-<UTC 時刻>.bak` へ退避。mac とは違う）。
  - クラッシュで残った `.lck` は開くのを妨げない。
- **測れなかったもの**: 古い版のファイル・ほかの Vectorworks が開いているファイル・メニューからの操作。測っている間に
  VW が 6 回落ちた（4 回は既知の描画の落ちで保存の振る舞いとは別物と読む【推定】。2 回は原因不明）。

### Windows——ほかの Vectorworks が開くファイルと、測れなかった残り（#291）

[issue #291](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/291)。描画で落ちない Windows を用意できないので、
測れた範囲と理由を書いて閉じた（[表と落ちた記録](../Metrics/Documents.md#windowsほかの-vectorworks-が開くファイルと測れなかった残り291)）。

- **2 つ目の Vectorworks はこの計算機では起動できない**（窓を出さずに消える。単一の起動に見える【推定】）。
- **外部のプロセスがファイルを書き込みで握っている状態が「使用中」の代わりになり、mac と同じくコピーに落ちる**
  （`OpenDocumentPath` は `true`・確認なしで `held コピー 1`・`fIsInMemoryOnly=yes`。元のファイルへの保存は 50331649）。
  **戻り値 `true` では気付けない。** 排他（`FileShare.None`）で握られていると `false`。
- **人が開く入口の確認の文言は mac と違う**（「ファイルは現在読み込み専用になっています（別のアプリケーションが使用している
  可能性があります）。…」。相手が VW だと分からない）。
- **古い版のファイルとメニューの操作は測れなかった**（メニューを開くと落ちる。`DoMenuName` は `Export MiniCAD File` も
  `Save` も **-3** で受け付けない。`Undo` と `Close` は通る）。
- **ブリッジとプローブからの操作だけなら落ちない。** 落ちたのはどれも画面の操作の後。
- **`vw_run_probe` は `new_document=false` の周でも図面を一時ファイルへ新しい名前で保存し直す**ので、走らせる周をまたぐ
  取り消しの段はブリッジの保存も込みの測定になる。

### 上書き保存の前に「書き込めない」と判定する（#293）

**問い**（[issue #293](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/293)）: 保存済みの図面を自分のパスへ
上書き保存する前に、どの OS の呼び出しで「ダイアログが出る」を当てられるか
（[Windows と mac の表・ダイアログの文言・OS への問い合わせの答え](../Metrics/Documents.md#上書き保存の前に書き込めないと判定する293)）。

**Windows**:

- **確実にダイアログ（2 枚。OK だけ）が出るのは「親のフォルダにファイルを足せない」とき**で、呼ぶ前に親のフォルダの
  `FILE_ADD_FILE` を聞けば当たる。そのとき **`GSError` は 0・`outSaved` も `yes` のままでファイルは変わらない**
  （「閉じる」で保存の確認が出る）。ダイアログの文言と違ってコピーはできていない。
- **ファイル自身の読み取り専用も書き込み拒否の ACL も 1 回目は断られず、ファイルは置き換わる**（VW は隣に新しいファイルを
  作って置き換えるので、ファイルの権限が効かない。置き換えの後は属性も ACL も消える）。
  **ただし読み取り専用にしたファイルは、続く保存で警告が出ることがある（7 回中 2 回。原因不明）。**
- **`CreateFileW(GENERIC_WRITE)` は判定に使えない**——開いている図面のファイルは書ける場面でも共有違反（32）。
  **`_waccess` は ACL を見ない。**
- **ファイル自身は書けるのに上書きできない**場面がある（権限の無いフォルダの中の書けるファイル。ダイアログ 3 枚）。
  **昇格しない利用者でも親のフォルダの答えだけが当たる。**
- `VW Backup\` は親の下の別のフォルダで、親への拒否（継承なし）は及ばない。

**mac**:

- **ダイアログが出るのは「ファイルが読み取り専用」「ファイルがロック」「親のフォルダに足せない」の 3 つで、呼ぶ前に
  ファイルと親のフォルダの `access(W_OK)` を聞けば漏れない。** 外れるのは書き込み拒否の ACL だけ（`access` は -1 だが
  ダイアログは出ず、ファイルは置き換わって ACE が消える）。
- **`GSError` はどの場面も 0**、`outSaved` も（ロックの 2 回目を除いて）`yes` のまま。ファイルが変わらない場面でもそう見える。
- **ロックの 2 回目で図面のパスがアプリのフォルダへ移る**（`chmod a-w` も #288 のとおり同じ）。`f-VWTMP.swap` と `.f.lck` が残る。
- **上書きはファイルをその場で書き換えない**（親に足せないと、ファイル自身が `open(O_WRONLY)` できても失敗する）。
- **`access(W_OK)` は ACL もロックも反映する**（Windows の `_waccess` と違う）。親のモードだけでは足りない。
- **Windows との違い**: mac はファイル自身の読み取り専用・ロックでもダイアログが出る。Windows は親のフォルダだけ。

### CLI の `save` への帰結（書き込めない。mac。#293）

- **`to` を省いた上書き保存の前に、ファイルと親のフォルダの両方へ `access(W_OK)` を聞き、どちらかが -1 なら `internal`（`file_read_only`）で断る。** これでダイアログの出る場面（上の 5 行）を漏らさない。ただし、**sticky のフォルダのほかの利用者のファイルはこれを通ってダイアログが出る**（「sticky ビットのフォルダの上書き保存（mac。#298）」）。
- **ファイルの書き込み拒否の ACL も断ることになるが、断ってよい**（ダイアログは出ないが、利用者が拒否したファイルを黙って置き換えて ACE を消すため）。ACL だけ通したいなら、ファイルの判定を「`st_flags` の `UF_IMMUTABLE` と、自分に書き込みの許可があるモードか」に替える。所有者以外のモードは測っていないので、既定は `access` にする。
- **失敗した保存を繰り返さない。** ロックの 2 回目で図面のパスがアプリのフォルダへ移る（`chmod a-w` も #288 のとおり同じ）。
- 呼んだ後の確かめには戻り値も `outSaved` も使えない。必要ならファイルの更新時刻を比べる（`chmod a-w` の場面は警告が出ても変わる）。

### CLI の `save` への帰結（書き込めない。Windows。#293）

- **`to` を省いた上書き保存の前に、親のフォルダへ `CreateFileW(FILE_ADD_FILE, FILE_FLAG_BACKUP_SEMANTICS)` で聞く。**
  アクセス拒否（5）なら `internal`（`file_read_only`）で断る。これでダイアログの出る場面を漏らさない。
- **`GetFileAttributesW` の `FILE_ATTRIBUTE_READONLY` も見て断る。** 1 回目はダイアログが出ないが、利用者が読み取り専用にした
  ファイルを黙って置き換えて属性を消すうえ、続く保存で警告が出ることがある（上の 7 回中 2 回）。
- **ファイルの書き込み拒否の ACL は断らなくてよい**（ACL の場面の保存 6 回でダイアログは出ていない。ただし ACE ごと消える）。
  見るなら `AccessCheck(FILE_GENERIC_WRITE)`。`_waccess` は ACL を見ないので使わない。
- **ファイルに `CreateFileW(GENERIC_WRITE)` しない**（図面を開いている間は必ず 32）。
- 呼んだ後の確かめには戻り値も `outSaved` も使えない。必要ならファイルの更新時刻を比べる。

### リンクを指す図面・削除を拒む ACE の上書き保存（Windows。#298）

**問い**（[issue #298](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/298)）: #293 の判定を通っても、
図面のパスがシンボリックリンクのとき・ファイルの削除が拒まれているときにダイアログで止まるか。昇格した VW で測った
（[表と OS への問い合わせの答え](../Metrics/Documents.md#リンクを指す図面削除を拒む-ace-の上書き保存windows298)）。

- **ファイルのシンボリックリンクは `OpenDocumentPath` で開けない**（VW はリンクを 0 バイトのファイルとして読む）。ハードリンクは開けるが、
  上書きするとリンクが切れる。
- 図面のパスがリンクになるのは**実体の無いリンクへ保存したとき**だけで、**次の上書きでリンクは通常のファイルに置き換わり、リンクの先は
  古いまま残る。ダイアログも `GSError` も出ない。** ダイアログが出るのは「リンクのあるフォルダ」に足せないときで、リンクの先のフォルダは
  関係ない。
- **親のフォルダがジャンクション・シンボリックリンクなら、図面のパスは文字列のまま残り、ファイルは先のフォルダで置き換わる**
  （リンクは残る）。先のフォルダに足せないとダイアログが出る。
- **削除の拒否でダイアログ（1 枚）が出るのは、ファイルの `DELETE` と親の `FILE_DELETE_CHILD` の両方が拒まれたときだけ。** 片方なら
  黙って置き換わる。**`CreateFileW(DELETE)` はこの 2 つを合わせた答えを返す**（5 ならダイアログ、32 は「消せるが VW が握っている」）。
- **親への問いは図面のパスの文字列から切り出す。** 解決した先で聞くと外れる。`AccessCheck` はジャンクション自身の ACL を見て外れる。
- リンクのパスの `GetFileAttributesW` は `FILE_ATTRIBUTE_REPARSE_POINT` を返す（リンクを追わない）。

### CLI の `save` への帰結（リンク・削除の拒否。Windows。#298）

- **親のフォルダは、図面のパスの文字列から切り出して聞く（リンクを解決しない）。** VW がファイルを足すのはリンクのあるフォルダで、先のフォルダを見るとダイアログを見逃すうえ、出ない場面を断る。
- **親への問いは #293 のまま `CreateFileW(FILE_ADD_FILE)` でよく、`AccessCheck` に替えない**（ジャンクションの下で見逃す）。ジャンクションそのものに拒否を付けた場面だけダイアログが出なくても断るが、珍しい場面で、断っても図面は失われない。
- **ファイルに `CreateFileW(DELETE, FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE)` で聞き、5 なら `internal`（`file_read_only`）で断る。** 32 は通す。`AccessCheck(DELETE)` だけで断ると、ダイアログの出ない場面まで断る。
- **`FILE_ATTRIBUTE_REPARSE_POINT` の付いたファイルへの上書きは断る。** 断らないとリンクが黙って通常のファイルに置き換わり、リンクの先の図面は古いまま残る。
  `to` に実体の無いリンクを渡す保存も同じ状態を作るので断る（`GetFileAttributesW` はリンクそのものを見るので、実体が無くても属性が返るはず【推定】）。
- 利用者がメニューからリンクを開いた場面は測っていない。

### リンクを指す図面の上書き保存（mac。#298）

[表と OS への問い合わせの答え](../Metrics/Documents.md#リンクを指す図面の上書き保存mac298)。

**結論（mac）: Windows と逆で、ファイルのシンボリックリンクは開けて、保存はリンクの先へ行き、リンクは残る。**

- **ファイルのリンクは 1 段だけ解決され、図面のパスは解決した先の文字列になる**（開いたときも保存先に渡したときも）。
  図面のパスがリンクのままになる場面は無い。
- **ダイアログが出るのは「リンクの先のフォルダ」に足せないときで、リンクのあるフォルダは関係ない**（Windows と逆）。
- **親のフォルダがリンクなら、図面のパスは文字列のまま残り**（Windows と同じ）、ファイルは先のフォルダで置き換わる。
- **2 段のリンクは開けない**（`false`）。実体の無い 2 段のリンクへ保存すると、**中間のリンクが通常のファイルに置き換わり、本当の先には
  何もできない。**
- 図面のパス（一覧の文字列）で `access(W_OK)` を聞けば当たる。リンクの文字列の親で聞くと外れる。

### CLI の `save` への帰結（リンク。mac。#298）

- **`to` を省いた上書き保存は #293 の判定のままでよい。図面のパス（一覧の文字列）のファイルと親へ `access(W_OK)` を聞く。** 図面のパスはもうリンクの先なので、追加で解決しない。親のフォルダがリンクの場面も `access` が追うので当たる。Windows の「文字列から切り出す」と同じ書き方で両方に当たる。
- **`to` に渡された文字列を `lstat` で見て、シンボリックリンクなら断る**（Windows の帰結と揃う）。断らないと次のことが起きる。
  - **自分の図面を指すリンクは「開いている図面との比較」をすり抜け**、上書きになる。先のフォルダに足せないと 2 枚のダイアログが出る。リンクの文字列の親へ聞いても当たらない。
  - 実体の無いリンクでは、保存先が渡した文字列と違うフォルダになる。2 段なら中間のリンクが通常のファイルに置き換わる。
- **`open` の結果は渡した文字列でなく、開いた後の図面のパスを返す**（リンクを渡すと先の文字列になる）。2 段のリンクと実体の無いリンクは `false` で断られる。
- 利用者がメニューや Finder からリンクを開いた場面は測っていない。

### sticky ビットのフォルダの上書き保存（mac。#298）

**結論: `chmod +t` のフォルダで、ファイルも親のフォルダも自分のものでないと、#293 の判定を通るのにダイアログで止まる。呼ぶ前に `stat` の持ち主と `S_ISVTX` で当たる。**
（[表](../Metrics/Documents.md#sticky-ビットのフォルダの上書き保存mac298)）

- ダイアログは 1 枚で、Windows の「ファイルに `(DE)`、親に `(DC)` の拒否」と同じ文言、**`.swap` が残るのも同じ**——**ファイルを消せない**
  ときの失敗と読める。`GSError=0`・ファイルは変わらない。
- `access(W_OK)`・`open(O_WRONLY)`・一時ファイルを作るは、どれも**ダイアログの有無を分けない**。分けるのは親の `S_ISVTX`・親とファイルの
  `st_uid`・`geteuid` だけ。
- 断らずに通る場面でも、**ほかの利用者のファイルの持ち主は黙って自分に変わる**。
- **`DoMenuName("Close", 0)` の保存の確認は、保存が失敗した印にならない**（リンクでない図面を開いて何も変えずに閉じても出た。
  上書き保存が通った後は出ない）。

### CLI の `save` への帰結（sticky。mac。#298）

- **`to` を省いた上書き保存の前に、#293 の `access(W_OK)` に足して、親のフォルダとファイルを `stat` し、親が `S_ISVTX` で、親の `st_uid` もファイルの `st_uid` も `geteuid()` と違うなら `internal`（`file_read_only`）で断る。** これでダイアログの場面を漏らさず、出ない場面（親かファイルが自分のもの）は断らない。
- `geteuid()` が 0（root）のときは測っていない。root なら規則上消せるので断らないのが自然である【推定】。
- **断らずに通る場面でも、ほかの利用者のファイルの持ち主は黙って自分に変わる**（sticky なしのフォルダと、自分が持ち主の sticky のフォルダ）。#293 の ACL で ACE が消えるのと同じで、VW がファイルを作り直すためと読める【推定】。
- **`.swap` は VW が消さない。** 判定で断れば残らない。

### 保存先のパスの形——UNC・`\\?\`・相対・`.` と `..`（#294）

**問い**（[issue #294](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/294)）: ドライブ文字から始まる絶対パス以外の形を
`SaveActiveDocumentPath` に渡すと、どこにどの名前で保存されるか
（[Windows・mac の表](../Metrics/Documents.md#保存先のパスの形unc相対-と-294)）。

**結論（Windows。`.` と `..` は mac も同じ）: 字面の処理は `IFileIdentifier::Set` が行い、ファイルシステムは見ない。`..` は畳まれるのに `.` は
残り、`..` は直前の段が `.` でも 1 段として消すので、`x\.\..\a.vwx` は `x\a.vwx` へ黙って保存される。`\\?\` は使えない。
UNC と `\\.\` は通り、渡した文字列がそのまま図面のパスになる。ダイアログはどの形でも出ない**（開いている図面と文字列が
同じときの「すでに開かれています」だけ）。

- Windows: `\\?\` は `\\%3F\` に化けて 50331649（**長いパスの逃げ道にならない**）。ドライブ相対は読み戻しが空で 50331652、ルート相対は先頭の `\` が
  落ちて 50331649。**読み戻しは `fileID->Set` の直後に分かる**ので、保存の前に読める。
- **`..` を畳んだ結果は開いている図面と比べられるが、`.` は残るので比べられない。**
- **同じファイルを別の文字列で `OpenDocumentPath` すると、自分が握っているのに使用中として扱い、確認なしにコピーで開く**（mac / Windows。
  `true` が返る）。同じ文字列なら `false`。
- UNC・`\\.\`・`.` を含むパスでも、同じ文字列での上書きと「閉じる」は通る。UNC の行は昇格した VW の結果。別の計算機の共有は測っていない。

**mac の結論: `.` と `..` の扱いは Windows と同じで、`x/./../a.vwx` は `x/a.vwx` へ黙って保存される。`//` は残らず畳まれる
（先頭の `//` も）。ダイアログは開いている図面と文字列が同じときの「すでに開かれています」だけ。**

- 保存の後で、渡した文字列を OS に聞くと「無い」と出る形がある（`nox/../`・`x/./../`）。**確かめるなら読み戻しの文字列で聞く。**

### 途中の段の末尾が `.` か空白の保存先（Windows。#299）

**問い**（[issue #299](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/299)）: 途中の段の末尾が `.` か空白だと、
どこにどの名前で保存されるか（[表](../Metrics/Documents.md#途中の段の末尾が--か空白の保存先windows299)）。

**結論: VW は文字列を直さず OS に渡す。`x.\` は Win32 の正規化で `x\` になるので、ファイルは `x\` に入るのに図面のパスは `x.\…` のまま残る
（`.` の段と同じく、開いている図面との比較から外れる）。`x..\` と `x \` は正規化されないので、その名前のフォルダが無ければ
50331649、あれば（`\\?\` でしか作れない）そこへ保存される。フォルダはどの場面でも作られず、ダイアログも出ない**（下の「足せないフォルダ」の場面を除く）。

- **`GetFullPathNameW` では検出できない**（`x..\`・`x \` を変えない）。**末尾の `.`・空白はパスの末尾に来ると落ちる**ので、親のフォルダの
  文字列を切り出して OS に聞くと別のフォルダの答えが返る——**`x..` にだけ拒否を付けると、#293 の判定は当たらずに 2 枚のダイアログで止まる**
  （親に一時ファイルを作る手だけは当たった）。
- 同じ文字列での上書きと「閉じる」は通る。`x\e.vwx` を `OpenDocumentPath` すると、`x.\e.vwx` を開いている自分を使用中と見てコピーで開く。
- **無題の図面の一覧のパスへの上書き**は、書き込める場所ならアプリのフォルダに `名称未設定 9` というファイルができる（昇格した VW）。
  `to` を省く上書きは無題の図面で呼ばない。

### CLI の `save` への帰結（パスの形。#294）

- **`to` は呼ぶ前に字面で正規化してから VW に渡す（mac・Windows とも）。** `.` の段を落とし、`..` を畳む（VW の処理に任せると、`.` が残るうえ
  `x\.\..\a.vwx`・`x/./../a.vwx` が別のフォルダに黙って保存される）。**`.` を先に落とす**（VW の順に合わせない）。正規化した文字列を比べれば
  `to_is_open` も `.` の違いに左右されない。
- **mac で受ける形**: `/` から始まる絶対パス。`//` は VW も畳むが、比べるために正規化の側でも畳む。シンボリックリンクを段に含むパスは
  測っていない（字面で畳むと OS の解決とずれうる。`/var` と `/private/var` は上の節のとおり直さない）。
- **以下は Windows の形。**
- **断る形**: `\\?\`（VW が受けないので `invalid_args` で理由を言う）・ドライブ相対・ルート相対（どれもダイアログは出ないが
  エラーの文を分かりやすくするため）・`\\.\`（通るが、図面のパスにデバイスの名前空間が残って以後の比較に使えない）。
- **途中の段の末尾が `.` か空白のパスも断る**（`invalid_args`。#299）。正規化では片付かない:
  `x.\` は `x\` に直せるが、`x..\` と `x \` は実在する別のフォルダを指しうるので直せない。残したまま受けると、親のフォルダの判定（#293）が
  別のフォルダを見てダイアログを断れない。**`GetFullPathNameW` では検出できない**（`x..\`・`x \` を変えない）ので、段の末尾を字面で見る。
  `.` と `..` だけの段は正規化で先に片付くので、ここの対象ではない。`\\?\` でしか作れない名前なので、断って困る場面は少ない【推定】。
- **受ける形**: ドライブ文字から始まる絶対パスと UNC。
- UNC と `C:\…` は同じファイルでも別の文字列で、比較では別物になる。既にあるファイルは VW が 50331649 で断るのでダイアログには
  ならず、放っておいてよい。
- 260 文字以上のパスは呼ぶ前に断ってよい（`\\?\` の逃げ道は無い。境目は `MAX_PATH`）。

### CLI の `save` への帰結（Windows）

mac の帰結に次を足す。

- **`to` は呼ぶ前に確かめる。** 区切りを `\` に直し、`< > : " | ? *` を含む名前を断る。VW に渡すと
  `GSError=0` のまま別の名前のファイルになり、成功と見分けが付かない。
- **保存の後は、前面の図面のパスを読み直して返す**（渡した文字列を返さない）。
- 「ファイルが消えた」の確認は Windows でも残す（ドライブが外れた場面でダイアログが出るため）。
- `to` と開いている図面の比較は、いまの予定のままでよい（大小違いは VW が断るが、緩く断っても害は無い）。
  **NFC にそろえて比べると、NFD の別のファイルへの保存も断ることになる**が、見た目が同じ図面が 2 枚並ぶほうが
  困るので断ってよい。

### 新しいパスへの保存で、親のフォルダに書き込めないとき（#304）

**問い**（[issue #304](https://github.com/min-nano/vectorworks-developer-sdk-reference/issues/304)）: 無題の図面を**まだ無いパス**へ保存する。
親のフォルダはあるがファイルを足せないとき、ダイアログが出るか。CLI の `save` は上書き保存を持たず、新しいパスへの保存だけにする
（#288・#293・#298 で上書き保存のダイアログを前もって確かめきれなかったため）
（[Windows・mac の表と問い合わせの答え](../Metrics/Documents.md#新しいパスへの保存で親のフォルダに書き込めないとき304)）。

**結論（Windows・mac 同じ）: ファイルを足せないときはダイアログなしで断られる（50331649）。ダイアログが出るのは、ファイルは足せるのに
保存先のフォルダに `VW Backup` フォルダを作れないとき**——そのときは**保存は通り**（`GSError=0`・`outSaved=yes`）、OK だけの警告
「バックアップフォルダを作成することができませんでした: …\VW Backup\」が保存のたびに出る。`VW Backup` を前もって作ってあれば出ない。
`VW Backup` という名前の**ファイル**があっても出る。

- **戻り値ではダイアログが出たか分からない。**
- **`icacls` の `AD` はファイルの追加ではない**（ディレクトリでは `WD`＝`FILE_ADD_FILE`、`AD`＝`FILE_ADD_SUBDIRECTORY`）。取り違えに注意。
- `VW Backup` を作るのは「保存の前のバックアップ」の設定による【推定：設定を切った場合は測っていない】。新しいパスへの保存でも作ろうとする。
- **Windows**: ファイルを足せるかを当てるのは「一時ファイルを作ってみる」だけ（読み取り専用のボリュームでは `CreateFileW` も `AccessCheck` も
  「書ける」と答える）。ただし外れても VW がダイアログなしで断るだけ。**`VW Backup` を作れない場面はどの問い合わせにも出ない。**
- **mac**: **`access(W_OK)` はディレクトリではファイルの追加とサブフォルダの追加の両方を見る**ので、親への `access(W_OK)` が 0 でなければ断る、で
  両方の場面をまとめて避けられる。**`VW Backup` という名前のファイルがある場面だけは通ってしまう**ので別に見る。
- 昇格しない利用者（Windows）・管理者でない利用者・ネットワークのボリューム（mac）は測っていない。

### CLI の `save` への帰結（新しいパスで書き込めない。#304）

mac は、保存先の親に `access(W_OK)` を聞いて −1 なら断る（ファイルを足せない場面と、`VW Backup` を作れない場面がどちらも −1 になる）。
そのうえで、保存先の `VW Backup` が**フォルダ以外のもの**としてあれば断る。Windows は次のとおり。


- **ファイルを足せない保存先は、VW がダイアログなしで断る（50331649）。** 前もって断るなら「一時ファイルを作ってみる」で
  当てられる（`FILE_ADD_FILE` の問い合わせは読み取り専用のボリュームを見逃す）が、見逃しても害は無い。
- **`VW Backup` を作れない保存先では、保存は通るのにダイアログが出る。** 呼ぶ前に、保存先のフォルダの `VW Backup` を見て、
  **フォルダとしてあればよし**、**無ければフォルダを作れるか**（実際に作って消すのが確か。`FILE_ADD_SUBDIRECTORY` の問い合わせで当たるかは測っていない【推定】）、
  **同じ名前のファイルがあれば断る**。作れない保存先は `internal` で断る。

### 呼んだ後の振る舞い（mac / Windows で実測）

詳細と数値は [Timers and Notifications](Timers%20and%20Notifications.md) の 4 の 9。ここには
文書の側から見た要点だけを置く。

- **呼び出しは戻る。** 図面を閉じ終えてから戻り（保存済み・図面 0 枚なら mac 99〜196 ms・
  Windows 711〜1287 ms）、**プロセスはその後に正常に終わる**（`atexit` まで届く。mac は
  4〜8 秒後・Windows は 28〜30 秒後）。
- **保存の確認は「未保存の変更」がある文書にだけ出る**（`bAskForSave=true`）。
  保存済みの文書・図面 0 枚なら確認なしで終わる。
- **確認で「キャンセル」すると、呼び出しはそのまま戻り、図面は開いたまま残る。**
  Vectorworks は動き続け、`gSDK` もふつうに呼べる。**戻り値が無いので、キャンセルされたことは
  `GetOpenFilesList()` の件数（減っていない）か、プロセスが生きていることで知る。**
- **確認の最中にもう一度呼ぶと、確認が 2 つ重なって出る。** 落ちはしない。Windows では
  呼んだタイマー自身が確認の最中に入り直すので、「呼び出しの最中」を旗で持って見送る。
- **`kNotifyBeforeApplicationQuit` は確認の前に届き、キャンセルされても届く。**
  「本当に終わる」合図にはならない。本当に終わるときは、最後に `plugin_module_main` へ
  `kPluginModuleDeinit`（-2）が届く（`atexit` の約 0.1 秒前）。

## 結論（プラグイン開発への示唆）

- **「周ごとにテンプレートから新しい図面を開いて、そこへ描く」は実機で成立する。**
  コマンド実行中に **`OpenDocumentPath(<テンプレートの .sta>, false)`** を呼べばよい。
  **テンプレートの中身を持った無題の新規文書**が開き、カレント文書も描画先も即座に移る。
  当初この筋は「テンプレート専用 API が無いので不可」と結論していたが、**それは誤り**
  だった——`Open` 側に `.sta` の扱いが入っている。
- **前の文書は開いたままにしても、閉じてもよい。** ハンドルは生きていて
  `SwitchToOpenFile` で行き来でき、読みも（名前の書き換えという範囲では）書きもできる。
  閉じたいなら `CloseDocument()` で閉じられる——**未保存でも閉じられる**。
- **【危険】`CloseDocument()` は確認せずに捨てる。** 保存確認ダイアログは出ず、未保存の
  変更は黙って消える。**人が編集中の文書を閉じない**こと——自分が開いた文書だけを対象に
  する（`outSaved` は「ディスクにあるか」でしかなく、**保存済みの文書の変更は見えない**）。
- **「未保存の変更があるか」は SDK から読めない。** 分かるのは「一度もディスクへ保存されて
  いない」（`fIsInMemoryOnly` / `outSaved`）までで、保存済みの文書を変更した状態は
  どちらにも現れない（上記「未保存の変更ありは読めない」）。
- **成否を戻り値で判定しない。** `CloseDocument()` も `SetObjectName()` も、成功しながら
  `false` を返す。**`GetOpenFilesList` の件数**や**読み戻した値**で確かめる。
- **「保存 → そのパスを開く」は続けて書かない。** 保存した時点でその文書自身がその
  ファイルなので、開き直しは `false` になる。閉じてから開く。
