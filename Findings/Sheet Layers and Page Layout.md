# 用紙（シートレイヤ）と割り付け

シートレイヤ上へ図を自動配置するときに要る SDK の実測。単位の癖が多く、**仮定した瞬間に
ずれる**ものばかりなので、読める値は読み、読めない値は「置いた後に測って動かす」で吸収する。

## 用紙の大きさは読めるが、単位に癖がある

- **用紙の大きさは SDK から読める**（`VWLayerObj::GetSheetWidht()` / `GetSheetHeight()`。
  綴りは SDK ママ）。ただし**返るのはインチ**（ヘッダのコメントが
  "value in inches. Use (result * 25.4) to get mm" と明記）。mm の図面では必ず換算する。
  オブジェクト変数では `ovLayerSheetWidth`（165）/ `ovLayerSheetHeight`（166）が同じ値。
- **「シートレイヤの大きさ」（165/166）と「用紙（ページ）そのものの大きさ」（167/168）は
  別の値。** さらに「印刷可能領域」も別物で、次項の余白から求める。

## 「用紙の大きさ」と「印刷可能領域」は別物で、余白を仮定してはいけない

余白は用紙ではなく**印刷の設定**が決めるものなので、定数で仮定した瞬間に実際とずれる
（狭く見積もれば図が 1 段階小さくなり、広く見積もれば印刷で切れる）。SDK には両方ある:
用紙は `ovLayerSheetPaperWidth` / `Height`（167 / 168）、**余白は
`ISDK::GetPageMargins(hLayer, left, right, bottom, top)`**（4 辺それぞれ）。

実例: 決め打ちの余白 15mm/辺に対し実際の余白は 3mm/辺しかなく、A3 横で使える幅が
390 → 414mm に増えて、同じ建物の図が 1/75 → 1/50 に 1 段階大きくなった。

## `GetPageMargins` だけ単位がヘッダに書かれていない【実機で確定】

用紙まわりの長さは SDK では一貫してインチだが、この 1 つだけ注記が無く、**実際は図面の
単位で返る**（mm の図面なら mm）。実測: 用紙 420 × 297 に対し
`左2.963 右3.006 下2.963 上2.963` が返り、引くと 414 × 291 ＝ シートレイヤの大きさ
（165 / 166）とぴったり一致した。

安全な解釈手順: 「インチとみなした値／mm とみなした値のうち、`用紙 − 余白` が
シートレイヤの大きさと一致する方」を採る。**判定を「mm 固定」にはしない**——単位が
図面依存である以上、インチの図面ではインチで返るはずで、そのときは同じ突き合わせで
インチが選ばれる。どちらとも一致しなければ用紙に収まる方（両方ならインチ）へ倒し、
**採った解釈と生の値は診断へそのまま出す**と、別の環境でも実機の数字で確かめられる。

- **余白の四辺 0 は「読めなかった」ではない。** 縁なし印刷ができる機種で余白 0 の
  用紙設定を選ぶと正当に 0 が返る。0 をエラー扱いすると「余白を解釈できなかった」という
  誤診断が出る。ただし**シートレイヤの大きさ（165/166）が用紙より小さいのに 0 が返った**
  ときだけは辻褄が合わない（印刷可能領域が狭いのだから余白は在るはず）ので、そのときは
  「解釈できなかった」側へ倒して生の値を診断に出す。**呼び出し自体が失敗して 0 のまま
  なのか、返ってきた 0 なのかも区別して持つ**（前者を「余白なし」と読んではいけない）。

## 用紙が図面座標のどこに在るかを返す呼び出しは無い

`GetSheetOrigin()` はあるが、それが用紙の中心を指すのか隅を指すのかはヘッダからは
決まらない（説明が無い）。意味の分からない値を使うより規約を 1 つ決める方がよいので、
**「用紙は原点を中心に置かれている」という前提**で矩形を組む（実機でこの前提の破綻は
出ていない）。印刷可能領域はそこから 4 辺の余白を引いた矩形で、**余白は左右・上下で
異なりうる**ので中心もそのぶんずれる（引いた後の矩形をそのまま使い、中心へ寄せ直さない）。
図が用紙の外に出ていたら、まずこの前提を疑うこと。

## 置いた後に測って動かす（位置合わせの作法）

- **ビューポートの実寸は描いてみるまで分からない**が、そこに何が映るかを呼び出し側が
  知っていれば縮尺は測る前に決められる。位置合わせだけは実物を測る（`GetObjectBounds` →
  `MoveObject`）。データタグ・グラフィック凡例と同じ「置いた後に測って直す」作法。
- **中身が流し込まれる PIO の実寸は、流し込み（`UpdateStyledObjects` / `ResetObject`）まで
  確定しない。** グラフィック凡例の幅は並ぶ中身で決まるので「これだけ空けておけば足りる」
  という定数は置けない（実測: 定数 150mm を空けたら実物は 25mm で、余りのせいで図が
  1 段階小さくなった）。「置く → 流し込む → `GetObjectBounds` で測る」の順で幅を得る。
- **ビューポートを動かすのはデータタグを置いた後。** タグは「注釈へ置いた実位置を測って
  目標との差だけ動かす」作りにするのが確実だが、**その実測はビューポートが用紙のどこに
  在るかに影響される**。先に動かすと全タグが同じ量だけ図から外れる（実機で確認）。注釈は
  ビューポートと一緒に動くので、**測る → タグを置く → 動かす**の順なら位置は保たれる。
- **ビューポートの縮尺をデザインレイヤから借りない。** デザインレイヤの縮尺は用紙に対する
  図の大きさとは関係が無く、図が用紙からはみ出しても気付けない。用紙と対象の大きさから
  決める。
